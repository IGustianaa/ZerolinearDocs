Konsep Combo

Combo adalah fitur unggulan 9Router yang menggabungkan beberapa model LLM menjadi satu nama. Saat aplikasi mengirim request dengan nama combo, 9Router memilih model mana yang dipakai berdasarkan strategi yang dikonfigurasi. Aplikasi tidak perlu tahu model mana yang digunakan — 9Router menangani pemilihan, routing, dan fallback secara transparan.

Manfaat combo:

  1. Reliability — Jika satu model/provider gagal, combo otomatis beralih ke model lain
  2. Cost optimization — Strategi round_robin atau priority dapat menggunakan model murah lebih sering
  3. Load balancing — Distribusi request ke multiple provider untuk menghindari rate limit
  4. Quality — Fusion mode dapat query multiple model dan pilih response terbaik
  5. Simplicity — Aplikasi hanya perlu tahu nama combo, bukan model individual

4 Strategi Combo

1. Priority

Model dicoba berdasarkan urutan priority. Jika model pertama gagal (error, timeout, rate limit), 9Router mencoba model kedua, dan seterusnya.

Combo: Skil1Ulti (strategy: priority)
 Priority 1: nvidia/z-ai/glm-5.2 <- Dicoba pertama
 Priority 2: aiand/zai-org/glm-5.2 <- Fallback jika #1 gagal
 Priority 3: bai/minimax-m3 <- Fallback jika #2 gagal
 Priority 4: deepseek/deepseek-chat-v4 <- Fallback jika #3 gagal
 Priority 5: minimax/minimax-m3 <- Fallback jika #4 gagal

Request flow:
 User -> 9Router -> Try #1 (nvidia/z-ai/glm-5.2)
 
AspekDeskripsi
-- Success -> Return response-- Fail -> Try #2 (aiand/zai-org/glm-5.2)
-- Success -> Return response-- Fail -> Try #3 ... (continue)

Cocok untuk: Production yang butuh reliability maksimum. Primary model dengan fallback chain.

2. Round Robin

Request didistribusikan secara bergantian (rotation) ke semua model dalam combo. Setiap request mendapat model berikutnya dalam antrian.

Combo: Skil1Hemat (strategy: round_robin)
 Model A: bai/minimax-m3 (weight: 1)
 Model B: deepseek/deepseek-chat-v4 (weight: 1)
 Model C: zhipu/glm-5.2 (weight: 1)

Request 1 -> Model A
Request 2 -> Model B
Request 3 -> Model C
Request 4 -> Model A (kembali ke awal)
Request 5 -> Model B
...

Jika salah satu gagal, 9Router skip ke model berikutnya dan coba lagi nanti.

Weight dapat menentukan rasio: weight 2 berarti model tersebut mendapat 2x lebih banyak request.

Cocok untuk: Distribusi beban, menghindari rate limit, penggunaan kuota yang merata.

3. Failover

Model "sticky" — 9Router tetap menggunakan model terakhir yang berhasil sampai gagal, lalu pindah ke model berikutnya dan tetap di sana.

Combo: Skil1Backup (strategy: failover)
 Primary: nvidia/z-ai/glm-5.2
 Backup: aiand/zai-org/glm-5.2
 Last: bai/minimax-m3

Timeline:
 Request 1-100 -> nvidia/z-ai/glm-5.2 (success, sticky)
 Request 101 -> nvidia/z-ai/glm-5.2 (FAIL)
 -> Switch to aiand/zai-org/glm-5.2
 Request 102-200 -> aiand/zai-org/glm-5.2 (sticky)
 Request 201 -> aiand/zai-org/glm-5.2 (FAIL)
 -> Switch to bai/minimax-m3
 Request 202+ -> bai/minimax-m3 (sticky)

Berbeda dari priority (yang selalu mencoba model pertama dulu), failover tetap di model fallback sampai model itu juga gagal.

Cocok untuk: Mengurangi overhead. Tidak perlu retry ke primary setiap request. Primary hanya dicoba ulang setelah cooldown.

4. Fusion

Semua model dalam combo di-query secara paralel. Judge model mengevaluasi semua response dan memilih yang terbaik.

Combo: Skil1Fusion (strategy: fusion)
 Models: nvidia/z-ai/glm-5.2, bai/minimax-m3, deepseek/deepseek-chat-v4
 Judge: aiand/zai-org/glm-5.2

Request flow:
 User -> 9Router
 
Item
-> Model A (nvidia/z-ai/glm-5.2) -> Response A
-> Model B (bai/minimax-m3) -> Response B (parallel)
-> Model C (deepseek/deepseek-chat-v4) -> Response C
v
 Judge Model: "Pilih response terbaik dari A, B, C"
 -> Evaluate quality, accuracy, completeness
 -> Select best response
 -> Return to user

Cocok untuk: Tugas kritis yang butuh kualitas tertinggi. Trade-off: biaya 3-4x lebih mahal (query semua model + judge).

Setup Guide dengan Dashboard

Step-by-step: Membuat Combo Priority

  1. Buka dashboard: http://localhost:20128
  2. Navigasi ke "Combos" -> "Create New"
  3. Isi:

- Name: Skil1Ulti

- Strategy: priority

- Kind: chat (atau completion)

  1. Tambahkan models:

- Model 1: nvidia/z-ai/glm-5.2 (priority 1)

- Model 2: aiand/zai-org/glm-5.2 (priority 2)

- Model 3: bai/minimax-m3 (priority 3)

- Model 4: deepseek/deepseek-chat-v4 (priority 4)

- Model 5: minimax/minimax-m3 (priority 5)

  1. Klik "Save"
  2. Test combo:
curl -X POST http://localhost:20128/v1/chat/completions -H "Authorization: Bearer your-key" -H "Content-Type: application/json" -d '{
 "model": "Skil1Ulti",
 "messages": [{"role": "user", "content": "Hello!"}]
 }'

Step-by-step: Membuat Combo Round Robin

  1. Dashboard -> Combos -> Create New
  2. Isi:

- Name: Skil1Hemat

- Strategy: round_robin

- Kind: chat

  1. Tambahkan models (semua weight 1 untuk distribusi merata):

- bai/minimax-m3 (weight 1)

- deepseek/deepseek-chat-v4 (weight 1)

- zhipu/glm-5.2 (weight 1)

  1. Save
  2. Setiap request akan bergantian: minimax -> deepseek -> zhipu -> minimax -> ...

Step-by-step: Membuat Combo Fusion

  1. Dashboard -> Combos -> Create New
  2. Isi:

- Name: Skil1Fusion

- Strategy: fusion

- Kind: chat

- Judge Model: aiand/zai-org/glm-5.2 (model yang mengevaluasi)

  1. Tambahkan models (2-4 model untuk fusion):

- nvidia/z-ai/glm-5.2

- bai/minimax-m3

- deepseek/deepseek-chat-v4

  1. Save

Model ID Format

Di combo, model ID wajib menggunakan prefix provider:

nvidia/z-ai/glm-5.2 <- Valid (provider: nvidia)
aiand/zai-org/glm-5.2 <- Valid (provider: aiand)
bai/minimax-m3 <- Valid (provider: bai)
deepseek/deepseek-chat-v4 <- Valid (provider: deepseek)
zhipu/glm-5.2 <- Valid (provider: zhipu)

z-ai/glm-5.2 <- ERROR (tidak ada prefix provider)
glm-5.2 <- ERROR (tidak ada prefix provider)

Nama combo sendiri (mis. Skil1Ulti) tidak memerlukan prefix — 9Router mengenalinya sebagai combo name.

Judge Model Concept

Dalam strategi fusion, judge model adalah model yang mengevaluasi dan memilih response terbaik dari multiple model. Judge model menerima:

  1. Original prompt/request dari user
  2. Response dari setiap model dalam combo
  3. Instruksi untuk mengevaluasi dan memilih

Judge model idealnya adalah model dengan reasoning kuat:

  • aiand/zai-org/glm-5.2 — Reasoning baik, harga wajar
  • nvidia/z-ai/glm-5.2 — Reasoning kuat
  • openai/gpt-4o — Premium, biaya tinggi

Judge model menambah biaya (satu request tambahan untuk evaluasi), tetapi meningkatkan kualitas response secara signifikan.

Fusion Mode Detailed

Fusion mode adalah strategi paling advanced. Alur lengkap:

1. User request masuk ke combo "Skil1Fusion"
2. 9Router kirim request ke SEMUA model dalam combo (paralel)
 - Model A: nvidia/z-ai/glm-5.2 -> Response A (1.2s, 500 token)
 - Model B: bai/minimax-m3 -> Response B (0.8s, 450 token)
 - Model C: deepseek/deepseek-chat-v4 -> Response C (1.5s, 520 token)
3. 9Router kirim ke Judge Model:
 "Berikut adalah 3 response untuk prompt: [original prompt]
 Response A: [response A]
 Response B: [response B]
 Response C: [response C]
 Pilih response terbaik berdasarkan akurasi, kelengkapan, dan kualitas.
 Return hanya response yang dipilih, tanpa penjelasan."
4. Judge Model mengevaluasi dan return response terbaik
5. 9Router return response terbaik ke user

Biaya fusion: 3 model + 1 judge = 4 request. Tetapi token saver dapat mengoptimasi ini.

Pitfall Section

Pitfall 1: Model ID Tanpa Prefix Provider

Masalah: Jika model ID tidak memiliki prefix provider (mis. glm-5.2 bukan nvidia/z-ai/glm-5.2), 9Router tidak dapat menemukan provider yang tepat dan mengembalikan error.

Solusi: Selalu gunakan format {provider}/{model}. Cek di dashboard -> Providers untuk melihat model ID yang benar.

Pitfall 2: Field kind Bernilai null

Masalah: Jika field kind pada combo bernilai null atau kosong, combo tidak akan berfungsi. 9Router tidak tahu apakah combo untuk chat completion atau text completion.

Solusi: Set kind ke chat (untuk chat completion) atau completion (untuk text completion). Via dashboard atau API:

curl -X PUT http://localhost:20128/api/combos/Skil1Ulti -H "Authorization: Bearer admin-key" -d '{"kind": "chat"}'

Pitfall 3: Tidak Perlu Restart Setelah Update Combo

Salah kaprah: Banyak yang mengira setelah mengubah combo (tambah/hapus model, ubah strategi), 9Router perlu di-restart.

Fakta: 9Router membaca konfigurasi combo dari database secara real-time. Perubahan di dashboard atau via API langsung berlaku tanpa restart. Request berikutnya akan menggunakan konfigurasi baru.

Pitfall 4: Fusion Tanpa Judge Model

Masalah: Combo dengan strategi fusion tetapi tanpa judge_model yang dikonfigurasi akan error. 9Router tidak tahu model mana yang akan mengevaluasi response.

Solusi: Selalu set judge_model saat menggunakan fusion.

Pitfall 5: Rate Limit Saat Round Robin

Masalah: Jika semua model dalam round_robin combo berasal dari provider yang sama, rate limit tetap berlaku karena provider yang sama membatasi total request.

Solusi: Gunakan model dari provider berbeda dalam round_robin combo untuk distribusi yang efektif.

Real Config Example

Berikut contoh konfigurasi lengkap 9Router combo yang digunakan di produksi:

# Combo 1: Skil1Ulti (Priority - Production)
name: Skil1Ulti
strategy: priority
kind: chat
models:
 - model_id: "nvidia/z-ai/glm-5.2"
 priority: 1
 - model_id: "aiand/zai-org/glm-5.2"
 priority: 2
 - model_id: "bai/minimax-m3"
 priority: 3
 - model_id: "deepseek/deepseek-chat-v4"
 priority: 4
 - model_id: "minimax/minimax-m3"
 priority: 5
token_saver: true
token_saver_threshold: 0.7

# Combo 2: Skil1Hemat (Round Robin - Hemat)
name: Skil1Hemat
strategy: round_robin
kind: chat
models:
 - model_id: "bai/minimax-m3"
 weight: 1
 - model_id: "deepseek/deepseek-chat-v4"
 weight: 1
 - model_id: "zhipu/glm-5.2"
 weight: 1

# Combo 3: Skil1Backup (Failover - Backup)
name: Skil1Backup
strategy: failover
kind: chat
models:
 - model_id: "nvidia/z-ai/glm-5.2"
 priority: 1
 - model_id: "aiand/zai-org/glm-5.2"
 priority: 2
 - model_id: "bai/minimax-m3"
 priority: 3

# Combo 4: Skil1Fusion (Fusion - Premium Quality)
name: Skil1Fusion
strategy: fusion
kind: chat
judge_model: "aiand/zai-org/glm-5.2"
models:
 - model_id: "nvidia/z-ai/glm-5.2"
 - model_id: "bai/minimax-m3"
 - model_id: "deepseek/deepseek-chat-v4"
token_saver: true

Konfigurasi di Hermes

# ~/.hermes/config.yaml
model:
 default: "Skil1Ulti" # Default: combo priority
 provider: "custom:9router"

custom_providers:
 9router:
 base_url: "http://localhost:20128/v1"
 api_key: "9r-sk-your-key"
 models:
 - "Skil1Ulti" # Combo: priority
 - "Skil1Hemat" # Combo: round_robin
 - "Skil1Backup" # Combo: failover
 - "Skil1Fusion" # Combo: fusion
 # Individual models (fallback)
 - "nvidia/z-ai/glm-5.2"
 - "bai/minimax-m3"

# Fallback ke direct provider jika 9Router down
fallback_providers:
 - provider: "custom:openai-direct"
 model: "gpt-4o-mini"
 condition: "all"

Dengan setup ini, Hermes menggunakan combo Skil1Ulti secara default. Jika semua model dalam combo gagal, fallback ke GPT-4o-mini langsung. Untuk tugas yang butuh hemat, switch ke Skil1Hemat. Untuk tugas kritis, gunakan Skil1Fusion.
