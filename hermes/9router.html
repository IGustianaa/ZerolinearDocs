Apa itu 9Router

9Router adalah self-hosted LLM gateway yang menyatukan akses ke 40+ LLM provider dalam satu endpoint. Berbeda dari OpenRouter yang cloud-based, 9Router berjalan di server sendiri — localhost, VPS, atau Termux — memberikan kontrol penuh atas data, routing, dan biaya.

Fitur utama 9Router:

  1. Single endpoint — Semua LLM diakses melalui http://localhost:20128/v1/chat/completions dengan format OpenAI-compatible
  2. Combo system — Gabungkan beberapa model menjadi satu nama dengan strategi rotasi (priority, round_robin, failover, fusion)
  3. Token saver (RTK) — Optimasi penggunaan token dengan menggabungkan response dari multiple model
  4. Key pool management — Kelola multiple API key per provider untuk menghindari rate limit
  5. Auto-fallback — Jika provider gagal, otomatis mencoba provider berikutnya
  6. Monitoring dashboard — Web UI untuk statistik real-time
  7. SQLite database — Semua config dan log tersimpan lokal

Installation

# Install via npm
npm install -g 9router

# Start 9Router
9r

# Default port: 20128
# Dashboard: http://localhost:20128

Verifikasi instalasi:

# Cek versi
9r --version

# Cek status
curl http://localhost:20128/v1/models

# Test request
curl -X POST http://localhost:20128/v1/chat/completions -H "Authorization: Bearer your-key" -H "Content-Type: application/json" -d '{
 "model": "bai/minimax-m3",
 "messages": [{"role": "user", "content": "Hello"}]
 }'

Startup

# Foreground (development)
9r

# Background (production)
nohup 9r > ~/.9router/9router.log 2>&1 &

# Dengan custom port
9r --port 20129

# Dengan custom database path
9r --db ~/.9router/custom/data.sqlite

Dashboard

Dashboard web tersedia di http://localhost:20128. Fitur dashboard:

  1. Provider Management — Tambah, edit, hapus provider connection. Set API key per provider.
  2. Combo Builder — Untuk dan edit combo secara visual. Pilih model, strategi, dan urutan.
  3. Request Statistics — Total request, token usage, cost, latency per provider dan per combo.
  4. Key Pool — Kelola multiple API key per provider. Lihat usage per key.
  5. Request Log — Log recent request dengan detail (model, token, latency, status).
  6. Health Check — Status setiap provider (online/offline, latency, error rate).

Provider Setup

Setiap provider dikonfigurasi dengan: nama, endpoint, API key, dan daftar model.

Via Dashboard

  1. Buka http://localhost:20128
  2. Klik "Add Provider"
  3. Isi: Name, Base URL, API Key
  4. Klik "Test Connection"
  5. Pilih model yang tersedia
  6. Save

Via API

# Add provider
curl -X POST http://localhost:20128/api/providers -H "Authorization: Bearer admin-key" -H "Content-Type: application/json" -d '{
 "name": "openai",
 "base_url": "https://api.openai.com/v1",
 "api_key": "sk-...",
 "models": ["gpt-4o", "gpt-4o-mini"]
 }'

# List providers
curl http://localhost:20128/api/providers -H "Authorization: Bearer admin-key"

# Test provider
curl -X POST http://localhost:20128/api/providers/openai/test -H "Authorization: Bearer admin-key"

Key Pool Management

Key pool memungkinkan multiple API key per provider untuk distribusi beban dan menghindari rate limit.

# Add key to pool
curl -X POST http://localhost:20128/api/providers/openai/keys -H "Authorization: Bearer admin-key" -d '{
 "api_key": "sk-second-key",
 "label": "OpenAI Key 2",
 "priority": 2
 }'

# Pool berisi:
# Key 1 (priority 1) - primary
# Key 2 (priority 2) - fallback saat key 1 rate limited
# Key 3 (priority 3) - fallback saat key 2 juga limit

Saat request masuk:

  1. 9Router cek key dengan priority tertinggi yang masih memiliki quota
  2. Jika key rate-limited (HTTP 429), otomatis switch ke key berikutnya
  3. Setelah cooldown, key kembali ke pool aktif

SQLite Database Schema

Database: ~/.9router/db/data.sqlite

Table: providerConnections

CREATE TABLE providerConnections (
 id INTEGER PRIMARY KEY AUTOINCREMENT,
 name TEXT UNIQUE NOT NULL, -- "openai", "anthropic", "9router"
 base_url TEXT NOT NULL, -- "https://api.openai.com/v1"
 api_key TEXT, -- Encrypted API key
 enabled INTEGER DEFAULT 1, -- 1=active, 0=disabled
 created_at TEXT DEFAULT CURRENT_TIMESTAMP,
 updated_at TEXT DEFAULT CURRENT_TIMESTAMP
);

Table: providerKeys

CREATE TABLE providerKeys (
 id INTEGER PRIMARY KEY AUTOINCREMENT,
 provider_id INTEGER NOT NULL, -- FK to providerConnections
 api_key TEXT NOT NULL,
 label TEXT, -- "OpenAI Key 1"
 priority INTEGER DEFAULT 1, -- 1=highest
 quota_used INTEGER DEFAULT 0, -- Token used this period
 quota_limit INTEGER, -- Max token per period
 rate_limited_until TEXT, -- Timestamp when cooldown ends
 enabled INTEGER DEFAULT 1,
 FOREIGN KEY (provider_id) REFERENCES providerConnections(id)
);

Table: combos

CREATE TABLE combos (
 id INTEGER PRIMARY KEY AUTOINCREMENT,
 name TEXT UNIQUE NOT NULL, -- "Skil1Ulti"
 strategy TEXT NOT NULL, -- "priority", "round_robin", "failover", "fusion"
 kind TEXT, -- Type of combo
 judge_model TEXT, -- For fusion: model that picks best response
 enabled INTEGER DEFAULT 1,
 created_at TEXT DEFAULT CURRENT_TIMESTAMP
);

Table: comboModels

CREATE TABLE comboModels (
 id INTEGER PRIMARY KEY AUTOINCREMENT,
 combo_id INTEGER NOT NULL, -- FK to combos
 model_id TEXT NOT NULL, -- "nvidia/z-ai/glm-5.2"
 provider_id INTEGER NOT NULL, -- FK to providerConnections
 priority INTEGER DEFAULT 1, -- Order in priority/failover
 weight INTEGER DEFAULT 1, -- Weight in round_robin
 FOREIGN KEY (combo_id) REFERENCES combos(id),
 FOREIGN KEY (provider_id) REFERENCES providerConnections(id)
);

Table: requestDetails

CREATE TABLE requestDetails (
 id INTEGER PRIMARY KEY AUTOINCREMENT,
 combo_id INTEGER, -- FK to combos (nullable for direct model)
 model_id TEXT NOT NULL, -- Actual model used
 provider_id INTEGER, -- Actual provider used
 input_tokens INTEGER,
 output_tokens INTEGER,
 latency_ms INTEGER, -- Time to complete
 status TEXT, -- "success", "error", "timeout"
 error_message TEXT,
 cost REAL, -- Calculated cost
 created_at TEXT DEFAULT CURRENT_TIMESTAMP,
 FOREIGN KEY (combo_id) REFERENCES combos(id),
 FOREIGN KEY (provider_id) REFERENCES providerConnections(id)
);

Combo System

Combo adalah fitur unggulan 9Router. Lihat halaman Combo & Strategy untuk panduan lengkap.

Ringkasan: combo menggabungkan beberapa model menjadi satu nama. Saat request menggunakan nama combo, 9Router memilih model berdasarkan strategi yang dikonfigurasi.

Token Saver (RTK)

Token Saver (RTK - Router Token Keeper) adalah fitur optimasi yang menghemat token dengan strategi cerdas:

Cara kerja:

  1. Request masuk ke combo dengan multiple model
  2. 9Router mengirim request ke model termurah terlebih dahulu
  3. Jika response confidence rendah atau tidak memuaskan, kirim ke model berikutnya
  4. Hanya charge token untuk model yang benar-benar digunakan

Hemat hingga 40% dibanding request paralel ke semua model.

# Enable token saver di combo
# Via dashboard: Combo Settings > Token Saver > Enable
# Atau via API:
curl -X PUT http://localhost:20128/api/combos/Skil1Ulti -H "Authorization: Bearer admin-key" -d '{
 "token_saver": true,
 "token_saver_threshold": 0.7
 }'

Monitoring

9Router menyediakan endpoint monitoring:

# Overall stats
curl http://localhost:20128/api/stats -H "Authorization: Bearer admin-key"

# Response:
# {
# "total_requests": 15420,
# "total_input_tokens": 45200000,
# "total_output_tokens": 12300000,
# "total_cost": 45.67,
# "avg_latency_ms": 850,
# "error_rate": 0.02
# }

# Per-provider stats
curl http://localhost:20128/api/stats/providers -H "Authorization: Bearer admin-key"

# Per-combo stats
curl http://localhost:20128/api/stats/combos -H "Authorization: Bearer admin-key"

# Recent requests
curl "http://localhost:20128/api/requests?limit=50" -H "Authorization: Bearer admin-key"
