Studi Kasus 1: Research Assistant

Problem Statement

Tim analis membutuhkan sistem yang dapat menerima topik penelitian, secara otomatis mencari sumber terkini, membaca dan mengekstrak informasi kunci, dan menghasilkan laporan terstruktur dengan citations. Volume penelitian: 20-50 topik per minggu. Tanpa agen, setiap topik membutuhkan 2-4 jam kerja manual.

Arsitektur

Research Assistant menggunakan arsitektur single deliberative agent dengan planning (Plan-and-Execute) dan lima tools:

  1. web_search — Mencari artikel, paper, dan laporan terkait topik
  2. fetch_page — Mengambil konten halaman web untuk dibaca
  3. summarize — Merangkum teks panjang menjadi bullet points
  4. extract_entities — Mengekstrak nama, tanggal, angka, dan fakta kunci
  5. write_report — Menyusun laporan final dalam format Markdown

Alur Eksekusi

Input: "Analisis dampak AI generatif terhadap industri media 2024-2025"

Step 1: Plan
 - Search for recent articles on AI + media industry impact
 - Search for industry reports (McKinsey, Deloitte, PwC)
 - Fetch top 5 most relevant sources
 - Extract key statistics and quotes
 - Identify trends and counterarguments
 - Write structured report with citations

Step 2-6: Execute each sub-task
 -> web_search("AI generatif dampak industri media 2024 2025")
 -> web_search("generative AI media industry report 2024 McKinsey")
 -> fetch_page(url1), fetch_page(url2), ...
 -> summarize(content), extract_entities(content)
 
Step 7: Synthesize
 -> write_report(findings, citations, format="markdown")

Kode Snippet

from langgraph.graph import StateGraph, END
from typing import TypedDict

class ResearchState(TypedDict):
 topic: str
 plan: list[str]
 findings: list[dict]
 report: str

def plan_research(state):
 prompt = f"Create a research plan for: {state['topic']}. Output as JSON list of steps."
 plan = llm.invoke(prompt)
 return {"plan": plan}

def execute_step(state):
 step = state["plan"][0]
 result = execute_with_tools(step, tools=[search, fetch, summarize])
 return {
 "findings": state["findings"] + [result],
 "plan": state["plan"][1:]
 }

def should_continue(state):
 if state["plan"]:
 return "execute"
 return "write_report"

workflow = StateGraph(ResearchState)
workflow.add_node("plan", plan_research)
workflow.add_node("execute", execute_step)
workflow.add_node("write_report", generate_report)
workflow.set_entry_point("plan")
workflow.add_edge("plan", "execute")
workflow.add_conditional_edges("execute", should_continue)
workflow.add_edge("write_report", END)

app = workflow.compile()
result = app.invoke({"topic": "AI impact on media industry", "findings": [], "report": ""})

Hasil dan Metric

  • Waktu per topik: 8-15 menit (vs 2-4 jam manual)
  • Akurasi citations: 92% (verified by human reviewer)
  • Cost per report: $0.05-0.20 (GPT-4o-mini untuk search, Claude Sonnet untuk writing)
  • Throughput: 50+ topik per hari dengan satu instance

Studi Kasus 2: DevOps Monitor

Problem Statement

Infrastruktur microservices dengan 200+ service membutuhkan monitoring 24/7. Tim on-call (5 orang) overwhelmed dengan 500+ alerts per hari, 80% false positive. Dibutuhkan agen yang dapat: memfilter noise, mengkategorikan alert, menjalankan remediasi otomatis untuk issue umum, dan escalate hanya yang membutuhkan manusia.

Arsitektur

DevOps Monitor adalah autonomous agent dengan level otonomi tinggi, berjalan melalui cron setiap 60 detik. Tools:

  1. query_metrics — Membaca Prometheus/Grafana metrics (CPU, memory, latency, error rate)
  2. query_logs — Mencari log entries dengan filter (ELK/Loki)
  3. run_command — Eksekusi shell command di server (dengan whitelist)
  4. scale_service — Scale up/down Kubernetes deployment
  5. restart_service — Restart pod atau container
  6. send_alert — Notify Slack/PagerDuty dengan severity dan context

Autonomy Levels

LevelTriggerActionApproval
L1: DetectMetric anomalyLog + classifyNone
L2: DiagnoseL1 confirmedQuery logs, identify root causeNone
L3: RemediateKnown issue (DB connection, OOM, disk)Auto-fix (restart, scale, clean)None
L4: EscalateUnknown or criticalNotify human with full contextHuman

Alur Eksekusi

[CRON every 60s]
1. query_metrics() -> detect: api-gateway latency p99 > 2000ms (threshold 500ms)
2. Classify: Severity HIGH, service: api-gateway
3. query_logs("api-gateway", "ERROR", last_5_min) -> found: "DB connection pool exhausted"
4. Match known issue: "DB connection pool exhaustion"
5. run_command("kubectl get pods -n api-gateway") -> 3 pods, 2 unhealthy
6. restart_service("api-gateway") -> pods recreated
7. query_metrics(after 30s) -> latency p99 = 350ms (recovered)
8. send_alert(slack, "AUTO-RESOLVED: api-gateway latency", context, actions_taken)

Guardrails

  • Action whitelist — Hanya restart, scale, dan clean cache. Tidak ada delete, deploy, atau config change.
  • Max actions per hour — 10 remediasi maksimum. Jika lebih, escalate ke manusia.
  • Rollback window — Setiap auto-fix dicatat. Jika metrik memburuk dalam 5 menit, rollback otomatis.
  • Circuit breaker — Jika 3 remediasi berturut-turut gagal, agent berhenti dan menunggu intervensi.

Hasil

  • Alert noise berkurang 73% (500 -> 135 per hari)
  • Auto-remediation success rate: 68% dari L3 issues
  • Mean time to resolution (MTTR): 45 menit -> 8 menit
  • Tim on-call workload: turun 60%, fokus shift ke L4 issues

Studi Kasus 3: Content Pipeline

Problem Statement

Media company memproduksi 30-50 artikel per hari. Proses manual: research -> draft -> edit -> SEO optimization -> publish. Butuh pipeline multi-agent yang mengotomasi end-to-end dengan quality control.

Arsitektur Multi-Agent

Pipeline menggunakan 4 specialist agents dalam konfigurasi sequential:

  1. Researcher — Menerima topic brief, cari trending angles, kumpulkan data dan sources
  2. Writer — Susun draft 1500-2000 kata berdasarkan research findings, dengan tone dan style guidelines
  3. Editor — Review draft untuk factual accuracy, grammar, flow, dan brand voice. Berikan revision notes.
  4. Publisher — SEO optimize (meta description, headings, keywords), format untuk CMS, schedule publish.

Implementasi dengan CrewAI

from crewai import Agent, Task, Crew, Process

researcher = Agent(
 role="Content Researcher",
 goal="Gather 5-7 authoritative sources and key data points for: {topic}",
 backstory="Experienced journalist with expertise in data-driven storytelling.",
 tools=[search_tool, scrape_tool, trend_tool],
)

writer = Agent(
 role="Content Writer",
 goal="Write a 1500-2000 word article from research findings.",
 backstory="Senior writer with 10 years at major publications. Adapts tone to brand guidelines.",
)

editor = Agent(
 role="Content Editor",
 goal="Review for accuracy, grammar, flow, and brand voice. Provide specific revision notes.",
 backstory="Former editor-in-chief. Meticulous about factual accuracy and readability.",
)

publisher = Agent(
 role="SEO & Publisher",
 goal="Optimize for SEO and format for WordPress CMS.",
 backstory="SEO specialist with technical content marketing expertise.",
 tools=[seo_tool, cms_tool],
)

tasks = [
 Task(description="Research {topic}", agent=researcher, expected_output="Research brief with 7 sources."),
 Task(description="Write article from research.", agent=writer, expected_output="1500-word draft."),
 Task(description="Edit and revise.", agent=editor, expected_output="Revised article + edit notes."),
 Task(description="SEO optimize and publish.", agent=publisher, expected_output="Published article URL."),
]

crew = Crew(agents=[researcher, writer, editor, publisher], tasks=tasks, process=Process.sequential)
result = crew.kickoff(inputs={"topic": "The future of quantum computing in 2025"})

Hasil dan Lessons Learned

  • Produksi: 30-50 artikel/hari dengan 1 human reviewer (vs 5 writers sebelumnya)
  • Kualitas: 85% published tanpa major revision (human reviewer fokus pada factual check)
  • Cost per artikel: $0.30-0.80 (mix of GPT-4o-mini untuk research, Claude Sonnet untuk writing)
  • Time per artikel: 5-10 menit end-to-end (vs 2-4 jam manual)

Pelajaran dari Implementasi

  1. Mulai simple — Ketiga studi kasus dimulai dengan single agent, lalu evolve. Jangan langsung multi-agent.
  2. Tools adalah segalanya — Kualitas agen 70% ditentukan oleh kualitas tool definitions dan deskripsinya. Invest waktu di sini.
  3. Human-in-the-loop awal — Jalankan dengan approval setiap langkah dulu, pelajari failure modes, lalu tingkatkan otonomi bertahap.
  4. Observability critical — Log setiap reasoning, tool call, dan result. Tanpa ini, debugging mustahil.
  5. Cost monitoring — Setiap agen harus track token usage. Tanpa ini, biaya bisa meledak diam-diam.
  6. Fallback strategy — Selalu memiliki rencana ketika LLM atau tool gagal. Agent yang crash di tengah task harus bisa resume.
