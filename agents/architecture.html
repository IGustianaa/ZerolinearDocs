Gambaran Umum

Arsitektur AI Agent modern terdiri dari lima komponen yang saling berinteraksi dalam sebuah reasoning loop. Setiap komponen memiliki tanggung jawab spesifik, dan kualitas agen ditentukan oleh seberapa baik komponen-komponen ini terintegrasi. Memahami arsitektur ini adalah prasyarat untuk memilih framework, mendesain tool, dan men-debug perilaku agen.

1. LLM Core (Inti Penalaran)

LLM Core adalah otak agen — model bahasa yang menerima konteks (instruksi, riwayat, hasil tool) dan menghasilkan keputusan: apakah memanggil tool, memberikan jawaban akhir, atau meminta klarifikasi. Pemilihan LLM Core memengaruhi seluruh aspek performa agen.

Pertimbangan pemilihan LLM Core:

  • Function calling reliability — Model harus konsisten menghasilkan JSON valid untuk tool invocation. GPT-4o dan Claude 3.5 Sonnet unggul di sini.
  • Context window — Agen mengakumulasi token cepat (system prompt + tool results + reasoning). Context 128K+ ideal untuk agen kompleks.
  • Reasoning depth — Untuk tugas multi-langkah, model dengan capability reasoning tinggi (o1, Claude Opus) mengurangi error.
  • Latency — Agen real-time butuh model cepat (GPT-4o-mini, Gemini Flash, Claude Haiku).

2. Memory (Memori)

Memori agen terdiri dari tiga lapisan yang masing-masing melayani kebutuhan berbeda:

Short-Term Memory (Memori Jangka Pendek)

Berisi konteks percakapan aktif dalam window LLM. Termasuk system prompt, instruksi terakhir, dan hasil tool yang masih relevan. Terbatas oleh context window model (4K-2M token). Strategi: sumarisasi konteks lama sebelum window penuh.

Long-Term Memory (Memori Jangka Panjang)

Penyimpanan persisten di luar context window. Implementasi umum: vector database (Pinecone, Chroma, Qdrant) untuk semantic retrieval, knowledge graph untuk relasi terstruktur, atau key-value store untuk data faktual. Agen dapat menyimpan pelajaran dari eksekusi sebelumnya dan mengambilnya saat dibutuhkan.

Working Memory (Memori Kerja)

State tugas sementara selama eksekusi: sub-tugas yang sedang berjalan, intermediate results, dan plan yang sedang dieksekusi. Di Hermes Agent, ini diimplementasikan sebagai state object yang ter-track per sesi.

3. Planning (Perencanaan)

Modul planning memecah tujuan kompleks menjadi sub-tugas yang dapat dieksekusi. Empat strategi utama:

ReAct (Reason + Act)

Agen bergantian antara reasoning ("Thought") dan action ("Action") dalam satu siklus. Setiap action menghasilkan observation yang masuk ke konteks berikutnya. Cocok untuk tugas yang relatif linear dengan feedback cepat.

Thought: Saya perlu mencari harga saham BBCA
Action: web_search("harga saham BBCA hari ini")
Observation: BBCA ditutup di Rp 9.750, naik 1.04%
Thought: Sekarang saya bandingkan dengan kemarin
Action: web_search("harga saham BBCA kemarin")
Observation: Kemarin Rp 9.650
Thought: Kenaikan 100 poin atau 1.04%. Saya bisa jawab sekarang.
Final Answer: Saham BBCA naik Rp 100 (1.04%) dari Rp 9.650 ke Rp 9.750.

Plan-and-Execute

Agen pertama membuat rencana lengkap (daftar langkah), lalu mengeksekusi satu per satu. Lebih terstruktur dari ReAct, tetapi kurang adaptif. Cocok untuk tugas dengan langkah yang dapat diprediksi.

Tree of Thoughts (ToT)

Agen menjelajahi multiple jalur reasoning secara paralel, mengevaluasi setiap cabang, dan memilih yang paling menjanjikan. Cocok untuk masalah dengan banyak solusi possible (math, puzzle, creative task). Komputasi mahal tetapi kualitas tinggi.

Reflexion (Self-Correction)

Agen mengevaluasi hasil eksekusinya sendiri, mengidentifikasi error, dan mencoba ulang dengan pendekatan berbeda. Setelah eksekusi, agen menulis "reflection" — apa yang berhasil, apa yang gagal, apa yang harus diubah. Refleksi ini disimpan di long-term memory untuk eksekusi mendatang.

4. Tools (Alat)

Tools adalah interface agen ke dunia luar. Setiap tool didefinisikan dengan JSON schema yang mendeskripsikan nama, deskripsi, dan parameter:

{
 "name": "search_web",
 "description": "Search the web for current information. Use for real-time data, news, prices.",
 "parameters": {
 "type": "object",
 "properties": {
 "query": {
 "type": "string",
 "description": "The search query"
 },
 "max_results": {
 "type": "integer",
 "description": "Maximum number of results",
 "default": 5
 }
 },
 "required": ["query"]
 }
}

Jenis tools umum: web search, code execution sandbox, file read/write, database query, HTTP API call, email/calendar integration. Prinsip utama: deskripsi tool harus jelas sehingga LLM tahu kapan menggunakan masing-masing.

5. Reasoning Loop (Siklus Penalaran)

Reasoning loop adalah inti dari agen — siklus observe-think-act yang berulang hingga tujuan tercapai atau kondisi berhenti terpenuhi.

Alur Step-by-Step

  1. Observe — Baca input pengguna dan state saat ini (context window, memory, previous tool results)
  2. Think — LLM menentukan langkah berikutnya berdasarkan tujuan, konteks, dan tools yang tersedia
  3. Act — Eksekusi tool yang dipilih atau hasilkan output akhir
  4. Evaluate — Periksa hasil: apakah berhasil? Apakah mendekati tujuan? Apakah perlu koreksi?
  5. Update — Tambahkan hasil ke memory, update working state
  6. Loop or Finish — Jika tujuan belum tercapai, kembali ke langkah 1. Jika tercapai, return hasil akhir.

Kode: Simple Agent Loop

import json

def agent_loop(goal, tools, llm, max_steps=10):
 context = [{"role": "user", "content": goal}]
 for step in range(max_steps):
 # 1. Think: LLM decides next action
 response = llm.chat(context, tools=tools)
 message = response.choices[0].message

 if message.tool_calls:
 for call in message.tool_calls:
 tool_name = call.function.name
 args = json.loads(call.function.arguments)
 # 2. Act: execute the tool
 result = tools[tool_name](**args)
 # 3. Observe: feed result back
 context.append({
 "role": "tool",
 "tool_call_id": call.id,
 "content": str(result)
 })
 else:
 # No tool call means agent is done
 return message.content

 return "Max steps reached without completion."

Pertimbangan Desain

Context Window Management

Agen mengakumulasi token sangat cepat. System prompt (2K), tool definitions (1K), setiap tool result (0.5-5K). Setelah 10-20 langkah, context bisa mencapai 50K+ token. Strategi: sumarisasi hasil lama, prioritaskan recent context, gunakan vector retrieval untuk long-term.

Tool Selection

Terlalu banyak tool membingungkan LLM (muncul tool selection error). Praktik terbaik: 5-15 tools per agen. Jika butuh lebih banyak, gunakan tool router — agen pertama memilih kategori, lalu sub-agen dengan tools spesifik.

Error Handling

Tool dapat gagal (API timeout, invalid input, rate limit). Agen harus menangani error gracefully: retry dengan backoff, fallback ke tool alternatif, atau melaporkan ke user. Never let one tool failure crash the entire loop.

Guardrails

Batasan keamanan untuk mencegah agen melakukan tindakan berbahaya: max iterations (mencegah infinite loop), tool whitelist (batasi tool yang dapat dipanggil), human-in-the-loop approval untuk tindakan sensitif (delete, deploy, payment), output filtering untuk mencegah data leakage.

Desain arsitektur yang baik menyeimbangkan otonomi dengan kontrol — agen cukup mandiri untuk efisien, tetapi cukup terbatas untuk aman dan dapat diaudit.
