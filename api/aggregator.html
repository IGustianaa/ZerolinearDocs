Apa itu Aggregator

Aggregator adalah platform perantara yang menyatukan akses ke banyak LLM provider dalam satu endpoint API. Alih-alih mendaftar ke setiap vendor secara terpisah, developer cukup mendaftar ke satu aggregator dan mendapatkan akses ke ratusan model. Manfaat utama: satu API key, satu base URL, satu format request, fallback otomatis antar provider, dan perbandingan harga yang transparan.

OpenRouter

OpenRouter adalah aggregator cloud-based paling populer. Dengan satu API key, developer mendapat akses ke 300+ model dari puluhan vendor termasuk OpenAI, Anthropic, Google, Meta, Mistral, dan banyak lagi. OpenRouter menggunakan format API OpenAI-compatible sehingga library standar dapat digunakan langsung.

Fitur unggulan OpenRouter:

  1. Multi-provider dalam satu endpoint — Beralih dari GPT-4o ke Claude 3.5 Sonnet hanya dengan mengubah nama model. Tidak perlu API key terpisah atau base URL berbeda.
  2. Pricing transparan — OpenRouter menampilkan harga setiap model termasuk markup kecil (biasanya 5-10% di atas harga vendor asli). Developer melihat biaya real-time per request.
  3. Fallback otomatis — Konfigurasikan fallback chain: jika provider A gagal, OpenRouter otomatis mencoba provider B untuk model yang sama.
  4. Ranking dan preferensi — OpenRouter melacak performa setiap provider dan dapat merute request ke provider tercepat atau termurah untuk model tertentu.
  5. Free tier — Beberapa model tersedia gratis dengan rate limit ketat, cocok untuk eksperimen.
from openai import OpenAI

client = OpenAI(
 api_key="sk-or-v1-...",
 base_url="https://openrouter.ai/api/v1"
)

# Akses model dari vendor berbeda dengan kode yang sama
models = ["openai/gpt-4o", "anthropic/claude-3.5-sonnet", "google/gemini-1.5-pro"]
for model in models:
 response = client.chat.completions.create(
 model=model,
 messages=[{"role": "user", "content": "Hello"}],
 )
 print(f"{model}: {response.choices[0].message.content}")

OpenRouter cocok untuk: prototyping cepat, A/B testing antar model, aplikasi yang butuh fleksibilitas multi-provider tanpa overhead manajemen API key. Kerugian: ada overhead latency 50-100ms, markup harga, dan tidak ada SLA guaranteed.

9Router

9Router adalah self-hosted LLM gateway yang memberikan kontrol penuh atas routing, fallback, dan optimasi biaya. Berbeda dari OpenRouter yang cloud-based, 9Router berjalan di server sendiri (localhost, VPS, atau Termux) dengan database SQLite lokal untuk tracking.

Fitur unggulan 9Router:

  1. Combo system — Gabungkan beberapa model menjadi satu nama. Contoh: combo Skil1Ulti dapat berisi 5 model dari 5 provider berbeda. Saat request masuk, 9Router memilih model mana yang dipakai berdasarkan strategi (priority, round_robin, failover, atau fusion).
  2. Token saver (RTK) — Fitur unik yang mengoptimasi penggunaan token dengan menggabungkan response dari beberapa model dan memilih yang terbaik, menghemat token hingga 40% dibanding request paralel penuh.
  3. Key pool management — Kelola multiple API key per provider. Saat satu key mencapai rate limit, 9Router otomatis beralih ke key berikutnya. Mendukung subscription provider dan free tier dalam satu pool.
  4. Auto-fallback — Jika provider gagal (timeout, 5xx error, rate limit), 9Router otomatis mencoba provider berikutnya dalam combo. Aplikasi tidak pernah melihat error.
  5. Monitoring dashboard — Web UI di http://localhost:20128 menampilkan statistik real-time: request count, token usage, cost, latency per provider, dan error rate.
  6. SQLite database — Semua konfigurasi dan log disimpan di ~/.9router/db/data.sqlite dengan tabel providerConnections, combos, dan requestDetails.
  7. OpenAI-compatible — Endpoint http://localhost:20128/v1/chat/completions kompatibel dengan library OpenAI standar.
# Konfigurasi 9Router di Hermes atau aplikasi apa pun
from openai import OpenAI

client = OpenAI(
 api_key="your-9router-key",
 base_url="http://localhost:20128/v1"
)

# Pakai combo name sebagai model
response = client.chat.completions.create(
 model="Skil1Ulti", # Combo: rotasi 5 model otomatis
 messages=[{"role": "user", "content": "Tulis kode Python untuk sorting"}],
)

9Router cocok untuk: production deployment yang butuh reliability maksimum, optimasi biaya melalui combo, self-hosted privacy, dan integrasi dengan Hermes Agent.

Together AI dan Fireworks AI

Together AI dan Fireworks AI berfungsi sebagai provider sekaligus aggregator untuk model open-weight. Together meng-host Llama, Mistral, DeepSeek, dan model lain dengan API OpenAI-compatible. Fireworks fokus pada latency rendah dengan inference engine yang dioptimasi. Keduanya menawarkan fine-tuning serverless.

Cloud Provider: Bedrock, Vertex, Azure

AWS Bedrock

AWS Bedrock menyediakan akses ke Claude, Llama, Titan, dan model lain melalui API AWS. Keunggulan: integrasi dengan ekosistem AWS (IAM, CloudWatch, Lambda), compliance enterprise, dan SLA. Endpoint: https://bedrock-runtime.{region}.amazonaws.com.

Google Vertex AI

Vertex AI adalah platform Google Cloud untuk LLM. Menyediakan Gemini dan model open. Keunggulan: integrasi Google Cloud, auto-scaling, dan Model Garden dengan ratusan model. Endpoint: https://{region}-aiplatform.googleapis.com.

Azure OpenAI

Azure OpenAI menyediakan model OpenAI (GPT-4, GPT-4o) di infrastruktur Azure. Keunggulan: compliance enterprise, data residency, private networking, dan Content Filtering yang dapat dikustomisasi.

Self-Hosted Gateway

vLLM

vLLM adalah inference server high-throughput untuk model open-weight. Mendukung PagedAttention untuk efisiensi memori tinggi. Cocok untuk produksi dengan GPU.

Ollama

Ollama menyederhanakan menjalankan model lokal. Satu command untuk download dan serve: ollama run llama3.1:70b. Cocok untuk development dan testing.

llama.cpp

Engine C++ untuk inference di CPU/GPU. Mendukung format GGUF dengan quantization. Cocok untuk perangkat terbatas (Raspberry Pi, laptop tanpa GPU).

Kapan Pakai Aggregator vs Vendor Direct

Pilih vendor direct jika:

  • Butuh latency terendah (setiap ms penting)
  • Hanya butuh satu model dari satu vendor
  • Butuh fitur proprietary (mis. prompt caching Anthropic)
  • Penggunaan rendah, tidak perlu multi-key

Pilih aggregator jika:

  • Butuh akses ke banyak model dari vendor berbeda
  • Ingin fallback otomatis untuk reliability
  • Ingin membandingkan kualitas dan harga antar provider
  • Butuh key pool untuk menghindari rate limit
  • Ingin satu endpoint untuk staging dan production
  • Menggunakan combo strategy (9Router)
