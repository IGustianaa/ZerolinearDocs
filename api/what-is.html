Apa itu API ProviderWhat is API Provider

BerandaHome / Apa itu API ProviderWhat is API Provider / Apa itu API Provider

Definisi

API Provider adalah layanan yang menyediakan akses terprogram ke model bahasa besar (LLM) melalui endpoint HTTP. Alih-alih meng-host model sendiri, developer mengirim request ke endpoint provider dan menerima respons berbasis teks. Ekosistem LLM terdiri dari tiga lapisan aktor yang sering membingungkan pemula:

  • Vendor — Organisasi yang melatih dan menerbitkan model. Contoh: OpenAI melatih GPT-4o, Anthropic melatih Claude 3.5 Sonnet, Google melatih Gemini. Vendor memiliki bobot model dan menjual akses langsung melalui API mereka sendiri.
  • Provider — Entitas yang menjalankan inference server dan menyediakan endpoint API. Vendor sering bertindak sebagai provider mereka sendiri (mis. api.openai.com), tetapi pihak ketiga juga dapat menjadi provider dengan meng-host model open-weight seperti Llama pada infrastruktur mereka sendiri.
  • Aggregator — Platform yang menggabungkan banyak provider ke dalam satu endpoint tunggal. Alih-alih mendaftar ke OpenAI, Anthropic, dan Google secara terpisah, developer cukup mendaftar ke aggregator dan mendapat akses ke semua model melalui satu API key dan satu base URL.
Diagram Ekosistem:

 Vendor (OpenAI) -----> Provider (api.openai.com) ----+
 Vendor (Anthropic) ---> Provider (api.anthropic.com) --+--> Aggregator (9Router / OpenRouter) --> Aplikasi Anda
 Vendor (Meta) -----> Provider (Together AI) +
 Self-hosted -----> Provider (vLLM lokal) -+

Lima Tipe Provider

1. Vendor Direct

Vendor itu sendiri yang menjalankan API. OpenAI, Anthropic, Google, dan Cohere berada di kategori ini. Keuntungannya adalah akses langsung ke model asli dengan latency terendah dan fitur terbaru. Kerugiannya adalah satu vendor = satu API key, satu rate limit, dan satu point of failure.

2. Cloud Provider

Platform cloud besar yang men-host model pihak ketiga. AWS Bedrock menyediakan akses ke Claude, Llama, dan Titan. Google Vertex AI menyediakan Gemini dan model open. Azure OpenAI menyediakan GPT dengan compliance enterprise. Keuntungannya adalah integrasi dengan ekosistem cloud (IAM, logging, networking) dan SLA enterprise.

3. Aggregator

Platform yang menggabungkan banyak provider. OpenRouter menawarkan 300+ model dari puluhan vendor. 9Router menawarkan self-hosted gateway dengan combo system. Keuntungannya adalah satu API key untuk semua model, kemampuan fallback otomatis, dan perbandingan harga transparan.

4. Open-Weight Hosting

Provider yang meng-host model open-weight. Together AI, Fireworks AI, dan Groq berada di sini. Mereka meng-host Llama, Mistral, dan model terbuka lainnya dengan harga kompetitif. Keuntungannya adalah biaya rendah dan opsi self-host.

5. Self-Hosted

Menjalankan inference server sendiri. vLLM, Ollama, dan llama.cpp memungkinkan hosting model di hardware sendiri. Biaya hanya compute, privasi maksimum, tetapi memerlukan keahlian GPU dan infrastruktur.

OpenAI-Compatible API Standard

Mayoritas provider mengikuti format API OpenAI. Ini berarti endpoint /v1/chat/completions menerima request dengan struktur yang sama, memungkinkan library seperti openai-python digunakan untuk berbagai provider hanya dengan mengubah base_url.

from openai import OpenAI

# OpenAI langsung
client_openai = OpenAI(api_key="sk-...", base_url="https://api.openai.com/v1")

# Anthropic via OpenRouter (OpenAI-compatible)
client_router = OpenAI(api_key="sk-or-...", base_url="https://openrouter.ai/api/v1")

# 9Router self-hosted
client_9r = OpenAI(api_key="9r-key", base_url="http://localhost:20128/v1")

# Together AI
client_together = OpenAI(api_key="...", base_url="https://api.together.xyz/v1")

# Semua menggunakan API call yang sama
response = client_9r.chat.completions.create(
 model="bai/minimax-m3",
 messages=[{"role": "user", "content": "Hello"}],
)

Kompatibilitas ini berarti kode aplikasi tidak perlu diubah saat berpindah provider. Hanya base_url, api_key, dan model yang berubah.

Struktur Endpoint

Endpoint standar mengikuti pola:

POST https://{base_url}/v1/chat/completions
GET https://{base_url}/v1/models
POST https://{base_url}/v1/embeddings
POST https://{base_url}/v1/images/generations

Body request untuk chat completion:

{
 "model": "gpt-4o",
 "messages": [
 {"role": "system", "content": "Anda asisten yang helpful."},
 {"role": "user", "content": "Jelaskan quantum computing"}
 ],
 "temperature": 0.7,
 "max_tokens": 1000,
 "stream": false
}

Metode Autentikasi

Bearer Token

Metode paling umum. API key dikirim di header Authorization:

curl https://api.openai.com/v1/chat/completions \
 -H "Authorization: Bearer sk-..." \
 -H "Content-Type: application/json" \
 -d '{"model":"gpt-4o","messages":[...]}'

API Key Header

Beberapa provider menggunakan header kustom:

# Google Vertex AI
curl ... -H "x-goog-api-key: AIza..."

# Azure OpenAI
curl ... -H "api-key: your-azure-key"

OAuth 2.0

Cloud provider seperti Google Vertex dan AWS Bedrock menggunakan OAuth:

# Google Vertex AI menggunakan access token dari gcloud
import subprocess
token = subprocess.check_output(["gcloud", "auth", "print-access-token"]).decode().strip()
headers = {"Authorization": f"Bearer {token}"}

Rate Limiting

Setiap provider membatasi jumlah request per menit (RPM) dan token per menit (TPM). Rate limit berbeda per tier:

TierRPMTPMKeterangan
Free3-6010K-100KUntuk eksperimen
Tier 1500150K-300KSetelah bayar $5+
Tier 250001M-5MPenggunaan aktif
EnterpriseCustomCustomNegosiasi

Saat rate limit tercapai, provider mengembalikan HTTP 429 dengan header Retry-After. Strategi mitigasi:

  1. Exponential backoff — Tunggu 1s, 2s, 4s, 8s saat retry
  2. Multi-key pool — Rotasi beberapa API key untuk distribusi beban
  3. Queue system — Taruh request di antrian, proses sesuai kapasitas
  4. Gateway — Gunakan 9Router atau OpenRouter yang menangani rate limit secara internal

Pagination

Beberapa endpoint (mis. GET /v1/models, log, batch results) mengembalikan data terpaginasi:

{
 "data": [...],
 "has_more": true,
 "next_cursor": "cursor_abc123"
}

Aplikasi harus mengikuti next_cursor hingga has_more false. Untuk data besar, gunakan batch API yang beberapa provider tawarkan dengan diskon 50% dibanding request individual.
