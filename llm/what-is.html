Apa itu LLMWhat is LLM

BerandaHome / Apa itu LLMWhat is LLM / Apa itu LLM

Definisi

Large Language Model (LLM) adalah model neural network yang dilatih pada volume teks berskala sangat besar (triliunan token) untuk memahami dan menghasilkan bahasa manusia. Inti dari LLM adalah kemampuan next-token prediction: diberikan urutan token, model memprediksi token berikutnya dengan probabilitas tertinggi. Ketika kemampuan ini di-scale ke miliaran parameter, muncul perilaku yang menyerupai pemahaman bahasa, reasoning, dan pengetahuan dunia.

LLM bukan database. Model tidak "menyimpan" informasi secara eksplisit; pengetahuan terenkripsi dalam bobot parameter sebagai pola statistik. Ini menjelaskan mengapa LLM dapat "tahu" fakta tetapi juga dapat hallucinate — pola yang dipelajari tidak selalu akurat.

Arsitektur Transformer

LLM modern dibangun di atas arsitektur Transformer, diperkenalkan oleh Vaswani et al. dalam paper "Attention Is All You Need" (2017). Transformer menggantikan arsitektur sekuensial (RNN/LSTM) dengan paralelisasi penuh, memungkinkan training pada skala masif.

Komponen Utama Transformer

Self-Attention Mechanism — Jantung dari transformer. Untuk setiap token dalam input, attention mechanism menghitung "relevansi" token tersebut terhadap semua token lain. Hasilnya: setiap token direpresentasikan sebagai kombinasi tertimbang dari semua token dalam konteks. Ini memungkinkan model menangkap hubungan jarak jauh (kata di awal kalimat mempengaruhi interpretasi kata di akhir kalimat).

Formula attention: Attention(Q, K, V) = softmax(Q K^T / sqrt(d_k)) V

Di mana Q (Query), K (Key), V (Value) adalah matriks yang diturunkan dari input. Token "bertanya" (Query) ke semua token lain (Key), dan jawabannya adalah kombinasi nilai (Value) dari token yang relevan.

Multi-Head Attention — Alih-alih satu attention, transformer menggunakan multiple "heads" yang berjalan paralel. Setiap head belajar pola yang berbeda: satu mungkin fokus pada sintaks, yang lain pada semantik, yang lain lagi pada coreference. Output dari semua heads digabungkan dan diproyeksikan kembali.

Positional Encoding — Transformer memproses semua token secara paralel, tidak ada urutan inherent. Positional encoding menambahkan informasi posisi ke setiap token. Metode modern (RoPE - Rotary Position Embedding) memungkinkan generalisasi ke context length yang lebih panjang dari yang dilihat saat training.

Feed-Forward Network (FFN) — Setelah attention, setiap token melewati FFN dua lapis dengan aktivasi non-linear (biasanya GELU atau SwiGLU). FFN menyimpan sebagian besar "pengetahuan" model — di sinilah fakta dan asosiasi disimpan.

Layer Normalization dan Residual Connections — Menstabilkan training pada kedalaman puluhan hingga ratusan lapis. Residual connection (skip connection) memungkinkan gradien mengalir langsung, mencegah vanishing gradient.

Decoder-Only Architecture

Mayoritas LLM modern (GPT, Claude, Llama) menggunakan decoder-only architecture. Token input diproses secara autoregressive: model memprediksi token ke-n hanya dari token 1 hingga n-1 (causal masking). Ini sederhana, scalable, dan terbukti efektif untuk generation tasks.

Pipeline Training

LLM modern dilatih melalui pipeline multi-tahap, masing-masing menyempurnakan kemampuan dan perilaku model.

1. Pre-training

Model dilatih pada korpus teks berskala besar (1-15 triliun token) dari web, buku, kode, dan paper. Objective: next-token prediction. Model belajar grammar, fakta dunia, reasoning patterns, dan kode. Pre-training menggunakan ribuan GPU selama berbulan-bulan, biaya $10-100+ juta untuk model frontier.

Output: base model — powerful tetapi tidak aligned. Base model akan "menyelesaikan" teks, bukan mengikuti instruksi. Berikan "What is 2+2?" dan model mungkin melanjutkan dengan "What is 3+3?" alih-alih menjawab.

2. Instruction Tuning (Supervised Fine-Tuning)

Base model di-fine-tune pada pasangan instruksi-respons berkualitas tinggi (10K-1M contoh). Model belajar mengikuti format instruksi: diberi pertanyaan, berikan jawaban. Transformasi dari &quot;text completion&quot; ke &quot;instruction following&quot;.
Annotator manusia membandingkan dua atau lebih respons dari model, menunjukkan mana yang lebih baik. Model reward dilatih untuk memprediksi preferensi manusia. Model utama kemudian dioptimasi menggunakan RL (biasanya PPO) untuk memaksimalkan reward. Hasil: respons lebih helpful, harmless, dan honest (HHH).

4. DPO (Direct Preference Optimization)

Alternatif RLHF yang lebih sederhana: langsung mengoptimasi model dari preference data tanpa melatih reward model terpisah. Lebih stabil, lebih cepat, dan menghindari kompleksitas RL. Banyak model modern (Llama 3, Mistral) menggunakan DPO atau variantnya.

Tokenization

Teks tidak diproses sebagai karakter atau kata, melainkan sebagai token. Tokenizer memetakan teks ke sequence of integers. Token dapat berupa kata, sub-kata, atau karakter, tergantung algoritma.

Contoh tokenization (BPE - Byte Pair Encoding):

"Hello world" -> [15496, 995] # 2 tokens
"Machine learning" -> [14881, 7563] # 2 tokens
"Tidak bisa" -> [29871, 9163, 1149] # 3 tokens (non-English lebih banyak)
"Artificial Intelligence" -> [5456, 11822] # 2 tokens
"AI" -> [9556] # 1 token

Token menentukan biaya API (dibayar per 1M token), kecepatan inference (lebih banyak token = lebih lambat), dan batas context window. Bahasa non-Inggris umumnya menggunakan lebih banyak token per kata karena tokenizer dioptimalkan untuk English.

Embedding

Embedding adalah representasi vektor numerik dari token atau teks. Setiap token dipetakan ke vektor berdimensi tinggi (768-12288 dimensi tergantung model). Token dengan makna serupa memiliki vektor yang berdekatan dalam ruang embedding.

Embedding memungkinkan: semantic search (mencari dokumen berdasarkan makna, bukan keyword), clustering (mengelompokkan teks serupa), dan RAG (Retrieval-Augmented Generation — mencari konteks relevan dari knowledge base untuk diberikan ke LLM).

Hukum Scaling

Performa LLM meningkat secara logaritmik dengan penambahan parameter, data, dan compute. Untuk mendapat peningkatan linier dalam kualitas, dibutuhkan peningkatan eksponensial dalam resource. Implikasi: doubling model size tidak doubling kualitas. Trade-off antara cost dan quality harus dianalisis per use case.

Cara Memilih Skala

  • Real-time chatbot — Small (3-8B) untuk latency rendah dan cost minim
  • Coding assistant — Large (70B+) untuk reasoning kompleks
  • Document analysis — Medium-Large dengan context window besar
  • Edge/mobile — Tiny (1-3B) yang dapat berjalan lokal
  • Research/frontier — Frontier models untuk kualitas terbaik

Pemahaman tentang arsitektur, training, dan scaling ini adalah fondasi untuk keputusan tentang vendor, model, dan strategi deployment yang akan dibahas di halaman berikutnya.
