Apa itu API Key

API key adalah string autentikasi yang mengidentifikasi dan mengotorisasi akses ke layanan LLM. Setiap request ke API vendor harus menyertakan API key di header HTTP. Vendor menggunakan key untuk: identifikasi akun, tracking usage dan billing, rate limiting, dan access control (model tertentu hanya tersedia untuk tier tertentu).

API key bukan sekadar password. Ia terikat ke akun dengan balance credit, memiliki rate limit berdasarkan tier, dan setiap penggunaan dikenakan biaya. Kompromi API key berarti seseorang dapat menggunakan kredit Anda — atau lebih buruk, jika key memiliki akses ke data sensitive, data tersebut dapat diakses.

Format API Key per Vendor

Setiap vendor memiliki format dan prefix yang khas:

VendorFormatPrefixContoh
OpenAIsk-... (51 char)sk-sk-proj-abc123XYZ...
Anthropicsk-ant-... (108 char)sk-ant-sk-ant-api03-abc123...
GoogleAIza... (39 char)AIzaAIzaSyB...
Mistral... (32 char)noneaBcDeFgH...
Zhipu{id}.{key}none123456.abcd1234...
DeepSeeksk-...sk-sk-deepseek123...
Cohere... (40 char)noneaBcDeFgH123...

Cara Mendapatkan API Key

OpenAI

  1. Daftar akun di platform.openai.com menggunakan email
  2. Verifikasi nomor telepon (wajib untuk mengaktifkan API access)
  3. Tambahkan payment method (credit card). Minimum deposit $5 untuk tier pertama
  4. Navigasi ke API Keys di sidebar
  5. Klik Create new secret key, beri nama deskriptif (misal "production-app")
  6. Pilih permissions: "All" atau "Restricted" (restricted lebih aman — batasi ke model tertentu)
  7. Copy key segera — tidak akan ditampilkan lagi setelah modal ditutup
  8. Set spending limit di Settings > Billing > Monthly budget untuk mencegah bill surprise

Anthropic

  1. Daftar akun di console.anthropic.com
  2. Verifikasi email dan nomor telepon
  3. Tambahkan payment method. Minimum credit $5
  4. Navigasi ke API Keys
  5. Klik Create Key, beri nama
  6. Copy key segera
  7. Set usage limit di Settings > Usage Limits

Google (Gemini API)

  1. Buka Google AI Studio di aistudio.google.com atau Google Cloud Console
  2. Login dengan Google account
  3. Untuk project baru atau pilih existing
  4. Enable Gemini API di APIs & Services > Library
  5. Navigasi ke Credentials
  6. Klik Create Credentials > API Key
  7. Pilih atau untuk API key. Restrict key ke Gemini API saja (security best practice)
  8. Copy key

Security Best Practices

1. Environment Variable, Bukan Hardcode

Jangan pernah menaruh API key di source code. Gunakan environment variable:
import os
api_key = os.environ.get("OPENAI_API_KEY")
if not api_key:
 raise ValueError("OPENAI_API_KEY not set")

2. .env File dengan chmod 600

Untuk development lokal, gunakan .env file dengan permission terbatas:

# .env file
OPENAI_API_KEY=sk-proj-xxx...
ANTHROPIC_API_KEY=sk-ant-xxx...

# Set permission
chmod 600 .env

# Python: load dengan python-dotenv
from dotenv import load_dotenv
load_dotenv()

Pastikan .env ada di .gitignore. Satu commit accidental ke public repo bisa mengorbankan ratusan dollar dalam hitungan menit.

3. .gitignore Wajib

# .gitignore
.env
.env.*
*.key
secrets/

4. Key Rotation

Rotate API key setiap 3-6 bulan. Jika key ter-expose (commit ke git, leak di log), rotate segera. Vendor memungkinkan revoke key lama dan create key baru tanpa downtime jika menggunakan multi-key pool.

5. Never Log API Keys

Logging middleware kadang tidak sengaja mencatat header Authorization:

# BAD: bisa leak key ke log
logger.debug(f"Request headers: {request.headers}")

# GOOD: redact sensitive headers
import re
safe_headers = {k: '***REDACTED***' if 'auth' in k.lower() or 'key' in k.lower() else v 
 for k, v in request.headers.items()}
logger.debug(f"Request headers: {safe_headers}")

6. Use Restricted Keys

Jika vendor mendukung (OpenAI), untuk key dengan scope terbatas: hanya model tertentu, hanya endpoint tertentu. Jika key ter-compromise, blast radius minimal.

7. Network-Level Protection

Di production, gunakan API key management service (AWS Secrets Manager, HashiCorp Vault, Doppler). Key tidak pernah menyentuh filesystem atau source code. Aplikasi fetch key saat startup dari vault.

8. Monitor Usage

Setup alerting untuk usage anomaly. Jika usage naik 10x dari normal, kemungkinan key ter-compromise atau ada bug yang menyebabkan infinite loop. Vendor menyediakan usage dashboard — set alert di threshold tertentu.

Multi-Key Pool Management

Untuk production dengan volume tinggi, single API key tidak cukup. Rate limit per-key menghambat throughput. Solusi: kelola pool of keys dengan strategi rotasi.

Round-Robin

Setiap request menggunakan key berikutnya secara berurutan. Distribusi merata. Implementasi sederhana:

import itertools

class KeyPool:
 def __init__(self, keys: list[str]):
 self._cycle = itertools.cycle(keys)
 self._keys = keys

 def next(self):
 return next(self._cycle)

pool = KeyPool(["sk-key1...", "sk-key2...", "sk-key3..."])
api_key = pool.next()

Priority with Fallback

Key utama dipakai duluan. Jika rate limited (429) atau error (500), beralih ke key fallback. Key utama dicoba lagi setelah cooldown:

class PriorityKeyPool:
 def __init__(self, primary: str, fallbacks: list[str]):
 self.primary = primary
 self.fallbacks = fallbacks
 self.primary_cooldown = 0

 def get_key(self):
 if time.time() > self.primary_cooldown:
 return self.primary
 elif self.fallbacks:
 return self.fallbacks[0]
 else:
 raise Exception("All keys exhausted")

Quota Tracking

Pantau usage per key. Jika satu key mendekati limit bulanan, otomatis kurangi frekuensi pemakaiannya. Implementasi: simpan counter per key di Redis, decrement setiap request, skip key yang di bawah threshold.

Rate Limiting

Setiap vendor menerapkan rate limit: requests per minute (RPM), tokens per minute (TPM), dan requests per day (RPD). Exceeding limit menghasilkan HTTP 429.

Strategi mengatasi: exponential backoff (retry dengan delay 1s, 2s, 4s, 8s), token bucket (request dibatasi per interval), dan queue (request di-antrikan saat rate limit tercapai).

import time
import random

def call_with_retry(func, max_retries=5):
 for attempt in range(max_retries):
 try:
 return func()
 except RateLimitError:
 delay = (2 ** attempt) + random.uniform(0, 1)
 time.sleep(delay)
 raise Exception("Max retries exceeded")

Cost Optimization

  • Model tiering — Gunakan model murah (GPT-4o-mini, DeepSeek) untuk 80% request, model mahal (Claude Sonnet) hanya untuk task kompleks
  • Prompt caching — Anthropic dan Google mendukung prompt caching: system prompt yang sama di-cache, mengurangi biaya input hingga 90%
  • Batch API — OpenAI Batch API memberikan diskon 50% untuk request non-real-time
  • Response length limit — Set max_tokens untuk mencegah output berlebihan
  • Caching — Cache respons untuk query identical. Redis atau in-memory cache

9Router Integration

9Router adalah API aggregator yang menyediakan single endpoint untuk multiple LLM vendor. Keunggulan: failover otomatis (jika vendor A error, beralih ke B), load balancing (distribusi request antar vendor), cost tracking terpusat, dan single API key untuk semua vendor.

# Konfigurasi 9Router — satu key untuk semua vendor
client = OpenAI(
 base_url="https://api.9router.com/v1",
 api_key=os.environ["NINEROUTER_API_KEY"]
)

# Request otomatis di-route ke vendor optimal
response = client.chat.completions.create(
 model="claude-3-5-sonnet", # route ke Anthropic
 messages=[{"role": "user", "content": "Hello"}]
)

9Router menangani: key management (Anda hanya memegang satu key), rate limit (distribusi across multiple vendor keys), failover (retry ke vendor berikutnya), dan cost analytics (dashboard usage per vendor). Ini mengurangi kompleksitas operasional secara signifikan untuk production multi-vendor.
