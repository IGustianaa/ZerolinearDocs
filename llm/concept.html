Token

Token adalah unit terkecil yang diproses LLM. Satu token kira-kira 0.75 kata dalam bahasa Inggris, atau sekitar 4 karakter. Token menentukan biaya API, kecepatan inference, dan batas context window.

Kalkulasi Token

import tiktoken

encoder = tiktoken.encoding_for_model("gpt-4o")

text = "Large Language Models are transforming how we interact with technology."
tokens = encoder.encode(text)
print(f"Text: {text}")
print(f"Token count: {len(tokens)}")
print(f"Tokens: {tokens}")
# Token count: 14
# Tokens: [43, 2278, 6868, 10417, 527, 44575, 1268, 586, 8474, 926, 4364, 13]

Estimasi cepat: 1 token = ~4 karakter = ~0.75 kata (English). 1.000 token = ~750 kata = ~2.5 halaman. Untuk bahasa Indonesia, rasio token per kata lebih tinggi (~1.3-1.5 token per kata) karena tokenizer tidak dioptimalkan untuk bahasa non-English.

Implikasi Praktis

  • Biaya — API charge per 1M token. Input dan output dihitung terpisah.
  • Context window — Total token (input + output) tidak boleh melebihi context window model.
  • Speed — Lebih banyak output token = lebih lama generasi. Output 1.000 token pada 80 TPS = 12.5 detik.

Context Window

Context window adalah jumlah maksimum token yang dapat diproses LLM dalam satu request (input + output combined). Model dengan context 128K dapat menerima ~96.000 kata input — setara buku 300 halaman.

Strategi Manajemen Context

Summarization — Saat percakapan panjang mendekati limit, sumarisasi bagian lama dan ganti dengan ringkasan. Menjaga konteks penting sambil menghemat token.

Chunking — Untuk dokumen besar, pecah menjadi chunk (500-2000 token), proses satu per satu, agregat hasil. Kombinasikan dengan RAG untuk retrieval selektif.

Sliding Window — Hanya pertahankan N pesan terakhir dalam context. Pesan lama di-drop. Cocok untuk chatbot di mana konteks jauh jarang relevan.

Vector Retrieval (RAG) — Simpan dokumen di vector database. Saat user bertanya, retrieve hanya chunk yang paling relevan (top-k) dan sertakan dalam context. Menghemat token secara dramatis.

# RAG pattern: retrieve relevant context
from chromadb import Client

Temperature

Temperature mengontrol randomness dalam pemilihan token. Nilai rendah = deterministik, nilai tinggi = kreatif/random.

Mekanisme

LLM menghasilkan distribusi probabilitas untuk token berikutnya. Temperature menskalakan distribusi ini sebelum sampling:

  • Temperature = 0 — Selalu pilih token dengan probabilitas tertinggi (greedy). Output deterministik.
  • Temperature = 1 — Sampling sesuai distribusi asli. Output bervariasi tetapi masih masuk akal.
  • Temperature > 1 — Distribusi diratakan, token low-probability lebih sering dipilih. Output menjadi aneh.

Contoh Output pada Berbagai Temperature

Prompt: "The meaning of life is"

[Temperature 0.0]
"The meaning of life is to find purpose and meaning in your existence."

[Temperature 0.7]
"The meaning of life is a deeply personal question that each person must answer for themselves."

[Temperature 1.0]
"The meaning of life is like a river flowing through mountains, sometimes calm, sometimes wild."

[Temperature 1.5]
"The meaning of life is purple octagons dancing in quantum soup."

Use CaseTemperatureAlasan
Code generation0.0 - 0.2Deterministik, precise
Data extraction0.0Consistent format
Q&A / Factual0.0 - 0.3Akurat, tidak kreatif

Fine-Tuning

Fine-tuning menyesuaikan model pre-trained untuk domain atau tugas spesifik. Diperlukan ketika prompt engineering dan few-shot tidak cukup.

LoRA (Low-Rank Adaptation)

LoRA membekukan parameter model asli dan menambahkan lapisan adapter kecil yang dilatih. Hanya adapter (biasanya <1% dari total parameter) yang di-update. Efisien, cepat, dan tidak merusak kemampuan asli model.

from peft import LoraConfig, get_peft_model
from transformers import AutoModelForCausalLM

model = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-3.1-8B")

lora_config = LoraConfig(
 r=16, # rank of adapter
 lora_alpha=32,
 target_modules=["q_proj", "v_proj", "k_proj", "o_proj"],
 lora_dropout=0.05,
 task_type="CAUSAL_LM"
)

model = get_peft_model(model, lora_config)
model.print_trainable_parameters()
# trainable params: 13.6M || all params: 8.07B || trainable%: 0.17%

# Train only the adapter
trainer.train(dataset) # 500-5000 examples, 3-5 epochs
model.save_pretrained("./lora-adapter") # save ~50MB (just adapter)

QLoRA adalah variant LoRA dengan model base di-quantize ke 4-bit, memungkinkan fine-tuning model 70B pada single GPU 24GB (RTX 4090). Standar untuk fine-tuning modern.

RLHF (Reinforcement Learning from Human Feedback)

RLHF menyelaraskan model dengan preferensi manusia melalui tiga tahap:

  1. Reward model training — Annotator membandingkan pasangan respons, reward model dilatih memprediksi preferensi
  2. Policy optimization — Model utama dioptimasi (via PPO) untuk memaksimalkan reward
  3. Iteration — Ulangi dengan data preferensi baru

RLHF kompleks, mahal, dan tidak stabil. Tetapi menghasilkan model yang lebih "aligned" — helpful, harmless, honest.

DPO (Direct Preference Optimization)

DPO menyederhanakan RLHF: langsung optimasi model dari preference data tanpa reward model terpisah. Lebih stabil, lebih cepat, dan hasil setara atau lebih baik dari RLHF pada banyak task. Formula:

L_DPO = -log(sigma(beta * (log_ratio(preferred) - log_ratio(dispreferred))))

Mayoritas model modern (Llama 3, Mistral, Zephyr) menggunakan DPO atau variant.

Quantization

Quantization mengurangi presisi numerik parameter model untuk menghemat memori dan mempercepat inference. Trade-off: sedikit penurunan kualitas, penghematan dramatis dalam ukuran dan kecepatan.

GGUF untuk CPU Inference

GGUF (GPT-Generated Unified Format) adalah format yang dioptimalkan untuk CPU inference dengan llama.cpp. Memungkinkan menjalankan model 70B pada laptop biasa (8-16GB RAM):

# Download quantized model
wget https://huggingface.co/.../llama-3.1-8b-q4_k_m.gguf

# Run with llama.cpp
./llama-server -m llama-3.1-8b-q4_k_m.gguf -c 4096 --port 8080

# atau dengan Ollama
ollama run llama3.1:8b

Inference Optimization

KV Cache

LLM menyimpan key-value pairs dari token yang sudah diproses untuk menghindari recomputation. Saat generating token ke-N, hanya token ke-N yang dihitung — token 1 hingga N-1 diambil dari cache. Ini mengubah kompleksitas dari O(n^2) ke O(n) untuk autoregressive generation.

Speculative Decoding

Model kecil (draft model) generate kandidat token, model besar verify secara batched. Jika kandidat benar, skip sequential generation. Speedup 2-3x tanpa loss kualitas.

Batching

Multiple request di-batch secara paralel melalui GPU. Throughput naik linearly dengan batch size hingga GPU memory penuh. Serving framework (vLLM, TGI) mengelola batching otomatis.

Flash Attention

Optimasi algoritma attention yang mengurangi memory access pattern. Speedup 2-4x dan memory reduction untuk long context. Didukung native di mayoritas model modern.

Memahami konsep-konsep teknis ini memungkinkan keputusan yang informed tentang konfigurasi model, optimasi biaya, dan strategi deployment. Setiap parameter — temperature, top-p, quantization level — memiliki trade-off yang harus dipahami dalam konteks use case spesifik.
