10 Golden Rules

1. AI adalah Assistant, Bukan Otoritas

AI menghasilkan kode yang plausible tetapi tidak selalu benar. Setiap baris dari AI harus melalui review manusia. AI dapat halusinasi: membuat function yang tidak ada, menggunakan API yang outdated, atau menghasilkan logic yang terlihat benar tetapi salah. Developer tetap bertanggung jawab penuh atas kode yang di-commit.

2. Spesifikasi adalah Segalanya

Kualitas output AI berbanding lurus dengan kualitas input. Prompt yang ambigu menghasilkan kode yang ambigu. Selalu berikan: requirement eksplisit, constraint, tipe input/output, error case, dan contoh.

# BURUK
"Tulis fungsi untuk proses data"

# BAIK
"Tulis fungsi Python yang:
- Input: list of dict dengan key 'name' (str) dan 'amount' (float)
- Output: dict dengan total amount per name
- Raise ValueError jika amount negatif
- Handle empty list (return {})
- Type hints wajib
- Pakai typing.Dict"

3. Context adalah Raja

AI hanya sebaik konteks yang diberikan. Berikan: existing pattern di project, convention, dependency version, dan contoh kode yang serupa. Gunakan tool dengan codebase context (Cursor, Windsurf) atau sertakan file terkait di prompt.

4. Iterasi, Jangan Sekali Jalan

Jangan harap AI menghasilkan kode production-ready dalam satu prompt. Pecah tugas kompleks menjadi langkah kecil. Generate draft, review, refine, repeat. Setiap iterasi mendekatkan ke hasil yang benar.

5. Test-Driven dengan AI

Tulis test sebelum kode. AI sangat baik dalam menghasilkan implementasi dari test spec. Test juga berfungsi sebagai spec yang executable.

# 1. Tulis test dulu
def test_calculate_discount():
 assert calculate_discount(100, 0.1) == 90
 assert calculate_discount(0, 0.5) == 0
 assert calculate_discount(100, 0) == 100
 with pytest.raises(ValueError):
 calculate_discount(-100, 0.1)
 with pytest.raises(ValueError):
 calculate_discount(100, 1.5)

# 2. Minta AI implementasikan
# 3. Run test, fix jika gagal

6. Jangan Blind Copy-Paste

Jika Anda tidak bisa menjelaskan kode yang dihasilkan AI, jangan commit. Pahami setiap baris. Jika tidak mengerti, tanya AI untuk jelaskan, atau pelajari konsepnya. Blind copy-paste adalah sumber bug dan security vulnerability.

7. Security First

AI tidak selalu mendeteksi vulnerability. Periksa manual: SQL injection, XSS, CSRF, path traversal, hard-coded secrets, insecure deserialization. Gunakan SAST tool (Bandit, Semgrep) sebagai lapisan tambahan.

8. Version Control Setiap Perubahan

AI dapat menghasilkan banyak kode cepat. Commit sering dengan message yang jelas. Jika AI membuat kesalahan, mudah rollback. Gunakan branch terpisah untuk eksperimen AI.

9. Dokumentasi Tetap Penting

AI dapat generate docstring dan README, tetapi review apakah dokumentasi akurat. Dokumentasi yang salah lebih buruk dari tidak ada dokumentasi.

10. Tahu Kapan TIDAK Pakai AI

AI tidak cocok untuk: arsitektur sistem kompleks (butuh konteks bisnis), optimasi performance low-level (butuh profiling), security-critical logic (butuh audit), dan domain-specific logic yang jarang muncul di training data. Gunakan judgment manusia untuk keputusan kritis.

Code Review Checklist untuk Kode AI

Sebelum merge kode yang dihasilkan AI, verifikasi:

  • [ ] Logic correctness — Apakah logic benar untuk happy path?
  • [ ] Edge cases — Apakah empty input, null, boundary value tertangani?
  • [ ] Error handling — Apakah try-catch ada dan meaningful? Tidak menelan error.
  • [ ] No hard-coded secrets — API key, password, token tidak ada di kode. Gunakan env var.
  • [ ] Input validation — Semua input external divalidasi (type, range, format).
  • [ ] SQL injection — Tidak ada string concatenation untuk query. Gunakan parameterized query.
  • [ ] XSS — Output di-escape sebelum render. Tidak ada dangerouslySetInnerHTML tanpa sanitization.
  • [ ] Dependency check — Library yang disarankan AI ada dan versi terbaru. Cek CVE.
  • [ ] Convention — Mengikuti project convention (naming, structure, pattern).
  • [ ] Performance — Tidak ada N+1 query, loop yang tidak perlu, atau memory leak.
  • [ ] Test coverage — Test ada dan meaningful. Bukan hanya happy path.
  • [ ] Type safety — Tidak ada any type (TypeScript) atau type annotation yang salah.

Testing Strategy

Unit Test

AI generate unit test, tetapi verifikasi:

# AI mungkin generate test yang hanya cek happy path
def test_sort():
 assert sort([3, 1, 2]) == [1, 2, 3] # OK tapi tidak cukup

# Tambahkan edge case yang AI lewatkan
def test_sort_edge_cases():
 assert sort([]) == [] # Empty
 assert sort([1]) == [1] # Single
 assert sort([1, 1, 1]) == [1, 1, 1] # Duplicates
 assert sort([3, 2, 1]) == [1, 2, 3] # Reverse
 assert sort([-1, 0, 1]) == [-1, 0, 1] # Negative
 with pytest.raises(TypeError):
 sort(["a", "b"]) # Wrong type

Integration Test

Test interaksi antar komponen. AI baik untuk generate mock dan fixture.

Property-Based Testing

Gunakan library seperti Hypothesis untuk generate test case secara otomatis:

from hypothesis import given, strategies as st

@given(st.lists(st.integers()))
def test_sort_property(lst):
 result = sort(lst)
 assert result == sorted(lst) # Always equal to built-in sort
 assert len(result) == len(lst) # Same length

Security Considerations

Jangan Paste Data Sensitif ke Prompt

API key, password, PII, dan data rahasia JANGAN dimasukkan ke prompt AI. Gunakan placeholder.

# BURUK: paste API key ke prompt
# "Fix this code: client = OpenAI(api_key='sk-abc123...')"

# BAIK: gunakan placeholder
# "Fix this code: client = OpenAI(api_key=os.environ.get('OPENAI_KEY'))"

Dependency Security

AI mungkin menyarankan library yang outdated atau memiliki vulnerability:

# Selalu check
pip audit # Python
npm audit # Node.js
safety check # Python alternative

Code Execution Risk

AI coding agent (Claude Code, Codex, Hermes) dapat menjalankan command. Batasi permission:

# Jangan run AI agent sebagai root
# Gunakan container/sandbox
docker run --rm -v $(pwd):/app -w /app coding-agent

# Atau restrict filesystem
# Hermes: enable hanya tool yang diperlukan

Team Workflow dengan AI

Solo Developer

  1. Spec -> AI draft -> Self-review -> AI test -> Self-verify -> Commit
  2. Gunakan AI sebagai "rubber duck" untuk diskusi arsitektur

Tim Kecil (2-5)

  1. Developer A: Spec + AI generate draft
  2. Developer B: Review + AI-assisted code review
  3. CI: AI tidak replace CI/CD pipeline yang sudah ada

Tim Besar

  1. Convention skill (Hermes) atau .cursorrules (Cursor) untuk konsistensi
  2. AI code review sebagai pre-check sebelum human review
  3. Track AI-generated code dengan tag di commit message

Common Anti-Patterns

Over-Engineering

AI cenderung menambahkan abstraction yang tidak perlu. "Just in case" code. Review dan hapus yang tidak digunakan.

Cargo Cult

AI menyarankan pattern karena sering muncul di training data, bukan karena cocok. Evaluasi apakah pattern benar-benar diperlukan.

Test Inflation

AI generate test yang lulus tetapi tidak menguji apa pun (assertion yang trivial). Review: apakah test gagal jika kode salah?

Prompt Dependency

Jika kode hanya bisa dimengerti dengan konteks prompt yang menghasilkannya, kode terlalu kompleks atau kurang self-documenting.

Prompt Patterns untuk Coding

Pattern: Spec-to-Implementation

Implement the following specification:
- Function: calculate_tax(amount, rate, region)
- Input: amount (float), rate (float 0-1), region (str)
- Output: float
- Rules:
 - region "id": PPN 11%, rate is additional
 - region "us": no additional
 - amount < 0: raise ValueError
 - Return rounded to 2 decimal places
- Type hints required
- Include docstring

Pattern: Refactor with Constraint

Refactor this function with these constraints:
- Must maintain backward compatibility (same signature)
- Must improve readability (extract helper functions)
- Must add type hints
- Must not change external behavior
- Max cyclomatic complexity: 5

Pattern: Debug with Context

I'm getting this error:
{stack_trace}

The code:
{code_snippet}

What I'm trying to do: {intent}
What I've already tried: {attempts}

Please:
1. Explain the root cause
2. Provide the fix
3. Explain why the fix works
4. Suggest how to prevent this in the future
