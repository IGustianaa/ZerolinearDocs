Filosofi Inti

Sebelum nulis SOUL.md, anda harus jelas dulu agent ini akan jadi siapa untuk anda.

Ada dua paradigma utama:

Paradigma 1: Agent sebagai Asisten

Agent adalah entitas terpisah dari anda. Dia bantu anda, tapi memiliki batasan jelas. Mirip asisten manusia yang kerja untuk anda.

Karakteristik:

  • Agent memiliki akun sendiri (kalau ada)
  • Agent tidak akses akun anda
  • Agent minta izin sebelum tindakan apapun
  • Agent bisa nolak request yang dia anggap berisiko

Cocok untuk: asisten administratif, customer service, chatbot publik, agent yang dipake banyak user.

Paradigma 2: Agent sebagai Perpanjangan Diri

Akun user = akun agent.

Agent adalah extension dari anda. Apa yang anda bisa lakukan di akun anda, agent anda bisa juga.

Karakteristik:

  • Agent akses penuh ke wallet, sosmed, GitHub, email anda
  • Agent bertindak atas nama anda
  • Agent tidak minta izin untuk hal-hal rutin
  • Agent cuma minta konfirmasi untuk yang irreversible
  • Anda bertanggung jawab penuh atas tindakan agent

Cocok untuk: personal AI agent, automation pribadi, sidekick teknis, agent single-user.

Guide ini fokus ke Paradigma 2 , karena itu yang paling powerful dan paling beda dari chatbot biasa.

Konsekuensi dari Paradigma 2

Kalau anda pilih paradigma "akun user = akun agent", anda harus terima:

1. Tanggung jawab penuh ada di anda

Kalau agent transfer wallet ke alamat salah, itu bukan salah agent — itu salah anda karena tidak setup verification dengan benar.

Tugas anda: membuat rule yang cukup ketat di SOUL.md biar agent tidak ngaco. Risk-gating untuk yang irreversible.

2. Credential management jadi krusial

Agent perlu akses credential, tapi credential tidak boleh muncul di chat (karena bisa ke-log, bisa ke-leak).

Pola yang sistem pake:

~/agent/credentials/

├── github.env (chmod 600)
├── wallet.env (chmod 600)
├── twitter.env (chmod 600)
└── README.txt

Agent cuma reference path. Cara pakainya:

source ~/agent/credentials/github.env && gh repo list

Token cuma di-export ke env var sesaat, tidak pernah muncul di output.

Detail lengkap di Manage Credentials.

3. Boundaries harus eksplisit

Karena agent bisa lakukan banyak hal, anda harus jelas apa yang tidak boleh dia lakukan:

  • Transfer ke alamat baru yang belum pernah dipake → konfirmasi
  • Delete repo → konfirmasi
  • Unfollow massal di sosmed → konfirmasi
  • Reply ke DM pribadi tanpa konteks → tidak boleh sama sekali

Detail di Boundaries.

4. Verification wajib

Agent tidak boleh bilang "udah selesai" tanpa bukti:

  • Setelah transfer → cek tx hash di explorer
  • Setelah post sosmed → cek URL post-nya
  • Setelah deploy → curl endpoint
  • Setelah commit → git status confirm clean

Detail di Verification.

## Filosofi sekunder

### Agent tidak ngehakimi user

Default disposition: asumsi user tahu apa yang dia lakukan.

Kalau user minta transfer crypto $5000 ke alamat baru, agent tanya konfirmasi sekali (ini high-risk), terus eksekusi. Bukan ceramah dulu soal risiko investasi.

Agent bukan moralizer, agent bukan financial advisor. Agent adalah eksekutor.

Agent jujur soal kemampuan

Kalau agent tidak bisa lakukan sesuatu (butuh GUI, captcha, credential tidak ada), bilang langsung. Jangan halusinasi hasil.

"Sistem tidak bisa solve captcha, anda perlu masuk sendiri sekali, habis itu cookie session-nya sistem pake."

Agent verify dirinya sendiri

Sebelum bilang &quot;done&quot;, verify dulu. Sebelum bilang &quot;gagal&quot;, debug dulu. Loop fix-verify maksimal 3x, gagal terus → escalate ke user.

Trade-off yang anda terima

Yang anda mendapat

AspekDeskripsi
Yang anda trade-offAutomation jauh lebih powerful
Resiko lebih tinggi kalau setup salahBot yang bener-bener melakukan handle
Harus aktif maintain SOUL.mdBisa lakukan task lintas-platform
Credential management overheadAgent yang konsisten kepribadiannya
Awalnya butuh effort setup

Filosofi Mahiru vs Guide ini

Guide Hermes/Mahiru fokus ke agent yang lebih "korporat" — partisipan terpisah dengan etika dan batasan sendiri. Cocok untuk agent yang dipake banyak orang.

Guide ini fokus ke agent personal mode "perpanjangan tangan". Cocok untuk single-user, full-trust setup. Trade-off keamanan vs power lebih agresif ke arah power.

Anda bisa pilih satu, atau mix sesuai kebutuhan. Yang penting: pilih dulu sebelum nulis SOUL.md.
