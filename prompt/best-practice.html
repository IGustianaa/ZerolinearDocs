10 Golden Rules of Prompt Engineering

Rule 1: Clarity Over Cleverness

Tulis prompt yang jelas dan langsung, bukan yang "pintar" atau berpuisi. Model tidak terkesan dengan gaya bahasa — yang diproses adalah token dan struktur. "Klasifikasi sentimen review berikut sebagai positif/negatif/netral" lebih baik dari "Bacalah jiwa pelanggan dari kata-kata berikut".

Rule 2: Show, Don't Just Tell

Few-shot examples lebih efektif daripada deskripsi verbal yang panjang. Satu contoh input-output mengkomunikasikan format dengan lebih tepat daripada paragraf instruksi. Jika format output kompleks, 3 contoh lebih murah daripada 200 kata deskripsi.

Rule 3: Decompose Complex Tasks

Pecah tugas kompleks menjadi langkah-langkah yang terpisah. Alih-alih "Analisis dokumen ini, rangkas, ekstrak entitas, klasifikasi, dan format sebagai JSON", gunakan pipeline: Step 1 ekstrak -> Step 2 klasifikasi -> Step 3 format. Setiap langkah lebih mudah diuji, debug, dan optimisasi.

Rule 4: Specify What NOT to Do

Negative instructions sama pentingnya dengan positive. "Jangan menambahkan komentar di luar JSON" mencegah model menambahkan teks penjelasan yang merusak parsing. "Jangan menggunakan informasi di luar konteks yang diberikan" mencegah halusinasi.

Rule 5: Control Output Length

Selalu tentukan panjang output yang diharapkan: jumlah kata, jumlah item, atau jumlah token. Tanpa batasan, model cenderung menghasilkan output yang lebih panjang dari yang diperlukan, membuang token dan biaya.

Rule 6: Use Delimiters for Structure

Gunakan penanda yang jelas untuk memisahkan komponen prompt: triple backticks, XML tags, atau delimiter kustom. Ini membantu model membedakan antara instruksi, konteks, dan data.

Instruksi: Ringkas teks di dalam <document> tags.

<document>
{konten_dokumen}
</document>

Output dalam format:
<summary>ringkasan</summary>
<key_points>point1; point2; point3</key_points>

Rule 7: Set the Right Temperature

Temperature mengontrol kreativitas output. Gunakan temperature 0 untuk tugas deterministik (klasifikasi, ekstraksi, parsing), 0.3-0.5 untuk summarization dan analisis, 0.7-0.9 untuk tugas kreatif. Jangan gunakan temperature tinggi untuk tugas yang membutuhkan konsistensi.

Rule 8: Test with Diverse Inputs

Jangan hanya menguji dengan input ideal. Untuk test suite yang mencakup: input kosong, input sangat panjang, input multilingual, input dengan karakter khusus, dan input adversarial. Prompt yang baik harus menangani edge case dengan graceful degradation.

Rule 9: Version Your Prompts

Prompt adalah kode. Simpan dalam version control, beri tag versi, dan dokumentasikan perubahan. Setiap perubahan prompt harus diuji terhadap regression test suite. "Small tweak" dapat mengubah perilaku secara tidak terduga.

Rule 10: Measure, Don't Assume

Jangan mengandalkan intuisi untuk menilai kualitas prompt. Definisikan metrik evaluasi (accuracy, precision, recall, BLEU, ROUGE, atau custom), jalankan pada test set, dan bandingkan secara kuantitatif. Prompt yang "terlihat lebih baik" belum tentu lebih akurat.

Anti-Patterns

Anti-Pattern 1: Prompt Everything

Mencoba menyelesaikan semua tugas dalam satu prompt raksasa. Ini menghasilkan output yang tidak konsisten dan sulit di-debug. Solusi: Pecah menjadi pipeline multi-step.

Anti-Pattern 2: Over-Engineering Prompts

Menambahkan constraint berlapis yang saling tumpang tindih. Setiap constraint tambahan meningkatkan kompleksitas dan dapat menyebabkan konflik. Solusi: Minimalisir, uji, lalu tambahkan hanya jika perlu.

Anti-Pattern 3: Copy-Paste Without Understanding

Menggunakan prompt dari internet tanpa memahami mengapa ia bekerja. Solusi: Pahami setiap komponen, uji pada data Anda sendiri, dan adaptasi ke konteks spesifik.

Anti-Pattern 4: No Fallback for LLM Failure

Tidak menangani kasus di mana model gagal atau menghasilkan output tidak valid. Solusi: Selalu implementasikan retry, fallback, dan output validation.

Anti-Pattern 5: Treating Prompts as Static

Prompt yang bekerja pada model versi lama mungkin tidak optimal pada versi baru. Solusi: Re-evaluate prompt saat model di-upgrade, dan maintain test suite yang dapat dijalankan ulang.

Prompt Testing Methodology

Test Set Construction

Bangun test set yang representatif dengan minimal 50-100 contoh yang mencakup:

  • Normal cases (70%): Input tipikal yang diharapkan
  • Edge cases (20%): Input ekstrem, kosong, atau tidak standar
  • Adversarial cases (10%): Input yang dirancang untuk menantang prompt

A/B Testing Prompts

A/B testing prompt adalah proses membandingkan dua atau lebih variasi prompt pada test set yang sama untuk menentukan mana yang berperforma lebih baik.

Proses A/B Testing

  1. Definisikan hipotesis: "Menambahkan few-shot example akan meningkatkan akurasi klasifikasi"
  2. Kontrol (A): Prompt saat ini
  3. Treatment (B): Prompt dengan perubahan
  4. Sample size: Minimal 100 test cases untuk signifikansi statistik
  5. Jalankan: Kedua prompt pada test set yang sama, temperature 0
  6. Analisis: Bandingkan metrik (accuracy, F1, latency, cost)
  7. Statistical test: Chi-square untuk accuracy, t-test untuk latency
from scipy import stats

def ab_test(prompt_a_results, prompt_b_results):
 a_correct = sum(1 for r in prompt_a_results if r["passed"])
 b_correct = sum(1 for r in prompt_b_results if r["passed"])
 
 # Chi-square test
 contingency = [
 [a_correct, len(prompt_a_results) - a_correct],
 [b_correct, len(prompt_b_results) - b_correct],
 ]
 chi2, p_value = stats.chi2_contingency(contingency)[:2]
 
 print(f"Prompt A: {a_correct}/{len(prompt_a_results)} "
 f"({a_correct/len(prompt_a_results)*100:.1f}%)")
 print(f"Prompt B: {b_correct}/{len(prompt_b_results)} "
 f"({b_correct/len(prompt_b_results)*100:.1f}%)")
 print(f"P-value: {p_value:.4f}")
 print(f"Significant: {'Yes' if p_value < 0.05 else 'No'}")

Prompt Versioning

Versioning Strategy

  • Semantic versioning: MAJOR.MINOR.PATCH (breaking.change.fix)
  • Branching: Main untuk production, feature branches untuk eksperimen
  • Changelog: Dokumentasikan apa yang berubah dan mengapa

Storage Structure

Team Collaboration on Prompts

Workflow Kolaborasi

  1. Prompt library: Centralized repository untuk semua prompt yang disetujui
  2. Review process: Pull request untuk perubahan prompt, review oleh senior prompt engineer
  3. Documentation: Setiap prompt dilengkapi dengan: deskripsi, use case, test results, known limitations
  4. Ownership: Setiap prompt memiliki owner yang bertanggung jawab atas maintenance
  5. Onboarding: Prompt library sebagai dokumentasi untuk anggota tim baru

Best Practices Tim

  • Gunakan bahasa yang sama untuk prompt dan dokumentasi (konsistensi ID/EN)
  • Standarkan format prompt (system + instruction + context + format)
  • Bagikan few-shot examples yang terbukti efektif
  • Conduct prompt review sessions secara berkala

Prompt Management Tools

LangSmith

Platform dari LangChain untuk tracing, evaluasi, dan manajemen prompt. Fitur utama:

  • Trace visualization: Lihat setiap langkah eksekusi dengan input/output
  • Prompt Hub: Versioned prompt repository yang dapat dibagikan
  • Evaluation framework: Automated testing dengan custom evaluators
  • Dataset management: Simpan dan kelola test datasets
  • Monitoring: Production tracing untuk observability real-time

Promptfoo

CLI tool untuk testing dan evaluasi prompt. Open-source, mendukung multiple providers.

# promptfooconfig.yaml
prompts:
 - file://prompts/sentiment_v2.txt

 - type: contains
 value: "positif"
 - vars: {input: "Rusak parah"}
 assert:
 - type: contains
 value: "negatif"
# Run evaluation
npx promptfoo eval

# View results in browser
npx promptfoo view
