Zero-Shot Prompting

Teknik paling mendasar: memberikan instruksi langsung tanpa contoh. Model mengandalkan pengetahuan dari training untuk memahami dan mengeksekusi tugas. Zero-shot efektif untuk tugas yang model sudah familiar: klasifikasi sentimen, ringkasan, translasi dasar, dan format konversi.

Kapan efektif: Tugas sederhana yang terdefinisi dengan jelas, model yang cukup besar (7B+), dan ketika biaya token harus diminimalkan.

Klasifikasikan sentimen review berikut sebagai 
"positif", "negatif", atau "netral". Hanya kembalikan 
label, tanpa penjelasan.

Review: "Pelayanan cepat tapi makanan biasa-biasa saja.
Lokasi strategis namun parkir sulit."

Output: netral

Kelebihan: Token efisien, cepat, biaya rendah. Kekurangan: Akurasi menurun pada tugas kompleks atau format yang tidak standar. Jika model salah memahami format output, tidak ada koreksi.

Few-Shot Prompting

Memberikan beberapa contoh input-output untuk menunjukkan pola yang diinginkan. Few-shot adalah salah satu teknik paling efektif untuk mengontrol format output, menetapkan tone, dan mengajarkan pola klasifikasi yang kustom.

Prinsip pemilihan contoh: Pilih contoh yang representatif, seimbang antar kelas, dan mendemonstrasikan edge case. Urutan contoh memengaruhi output — model cenderung memberi bobot lebih tinggi pada contoh terakhir.

Klasifikasikan sentimen:

Review: "Luar biasa! Pengalaman tak terlupakan." -> positif
Review: "Mengecewakan total, tidak akan kembali." -> negatif 
Review: "Harga standar, pelayanan standar." -> netral
Review: "Tempatnya nyaman tapi makanan hambar." -> netral
Review: "Wah, presentasinya keren banget!" -> positif
Review: "Lambat sekali, 45 menit untuk secangkir kopi." -> negatif

Review: "Desain interior bagus, tapi AC mati." ->

Optimisasi few-shot:

  • Gunakan 3-7 contoh (lebih dari itu, diminishing returns)
  • Acak urutan contoh antar run untuk mengurangi position bias
  • Pertimbangkan dynamic few-shot: pilih contoh berdasarkan kemiripan dengan input (retrieval)

Chain-of-Thought (CoT)

Meminta model menalar langkah demi langkah sebelum memberikan jawaban akhir. CoT secara dramatis meningkatkan akurasi pada tugas reasoning, matematika, logika multi-step, dan analisis kompleks.

Mengapa efektif: LLM adalah next-token predictor. Tanpa CoT, model harus "menahan" seluruh reasoning dalam bobot tersembunyi dan menghasilkan jawaban langsung. Dengan CoT, setiap langkah reasoning menjadi token yang tersedia sebagai konteks untuk langkah berikutnya, secara efektif memberikan model "scratchpad".

Soal: Sebuah toko menjual apel Rp 3.000/buah. 
Diskon 20% jika beli lebih dari 10 buah. Pajak 11%.
Berapa total harga 15 buah apel?

Pikirkan langkah demi langkah:

Langkah 1: 15 buah > 10, jadi dapat diskon 20%
Langkah 2: Harga sebelum diskon = 15 x 3000 = 45.000
Langkah 3: Diskon = 20% x 45.000 = 9.000 
Langkah 4: Harga setelah diskon = 45.000 - 9.000 = 36.000
Langkah 5: Pajak = 11% x 36.000 = 3.960
Langkah 6: Total = 36.000 + 3.960 = 39.960

Jawaban: Rp 39.960

CoT otomatis (zero-shot CoT): Cukup tambahkan "Mari pikirkan langkah demi langkah" di akhir prompt. Sederhana namun efektif untuk banyak kasus.

Self-Consistency

Teknik yang menjalankan CoT multiple kali dengan temperature tinggi, lalu memilih jawaban mayoritas. Self-consistency mengurangi variance dan meningkatkan akurasi pada tugas di mana hanya ada satu jawaban benar (matematika, logika, klasifikasi).

Implementasi:

import openai

def self_consistent_answer(question, n=5):
 answers = []
 for _ in range(n):
 response = openai.chat.completions.create(
 model="gpt-4o",
 messages=[{"role": "user", "content": 
 f"{question}\n\nPikirkan langkah demi langkah."}],
 temperature=0.7, # High temp for diversity
 )
 answers.append(response.choices[0].message.content)
 
 # Extract final answer from each, vote
 final_answers = [extract_answer(a) for a in answers]
 from collections import Counter
 return Counter(final_answers).most_common(1)[0][0]

Trade-off: Membutuhkan n-kali biaya API. Gunakan untuk tugas kritis di mana akurasi lebih penting daripada biaya. Untuk tugas klasifikasi, n=5 biasanya optimal.

ReAct (Reason + Act)

Pola yang menggabungkan reasoning dengan tool use. Model menalar, memutuskan tindakan, mengamati hasil, lalu menalar lagi dalam loop hingga mencapai jawaban. ReAct adalah dasar dari hampir semua AI agent modern.

Struktur loop: Thought -> Action -> Observation -> Thought -> Action -> ... -> Final Answer

Pertanyaan: Berapa populasi ibu kota negara dengan 
GDP tertinggi di Asia Tenggara?

Thought: Saya perlu mencari negara Asia Tenggara 
dengan GDP tertinggi.
Action: search("GDP tertinggi Asia Tenggara 2024")
Observation: Indonesia memiliki GDP tertinggi di 
Asia Tenggara, sekitar $1.3 triliun.

Thought: Ibukota Indonesia adalah Jakarta. Saya 
perlu populasi Jakarta.
Action: search("populasi Jakarta 2024")
Observation: Populasi Jakarta diperkirakan 10.6 
juta jiwa (2024).

Thought: Saya memiliki jawabannya.
Final Answer: Ibukota negara dengan GDP tertinggi 
di Asia Tenggara adalah Jakarta (Indonesia), dengan 
populasi sekitar 10.6 juta jiwa.

Tree of Thoughts (ToT)

Generalisasi CoT yang menjelajahi multiple jalur reasoning secara paralel, mengevaluasi setiap cabang, dan memilih jalur terbaik. ToT efektif untuk masalah dengan banyak solusi yang mungkin: game tree, perencanaan strategis, dan optimisasi.

Proses:

  1. Generate N kandidat langkah reasoning awal
  2. Evaluasi setiap kandidat (LLM sebagai evaluator atau heuristic)
  3. Prune kandidat dengan skor rendah
  4. Expand kandidat tersisa (BFS atau DFS)
  5. Ulangi hingga solusi ditemukan atau kedalaman maksimum tercapai

Contoh use case: "Susun jadwal 5 meeting untuk 10 orang dengan constraint: 3 orang hanya bisa pagi, 2 orang zona waktu berbeda, hindari bentrokan."

ToT mengeksplorasi multiple konfigurasi paralel, mengevaluasi feasibility setiap cabang, dan backtrack jika menemui deadlock. Jauh lebih kuat dari CoT linear untuk masalah constraint satisfaction.

Role Prompting

Memberikan peran atau persona spesifik untuk mengaktifkan pengetahuan domain dan mengatur tone output. Role prompting bukan sekadar dekorasi — studi menunjukkan bahwa model benar-benar menyesuaikan distribusi output berdasarkan persona yang diberikan.

Anda adalah arsitek software dengan 20 tahun pengalaman 
di sistem terdistribusi. Review design berikut dengan 
fokus pada:
1. Scalability bottlenecks
2. Single points of failure 
3. Data consistency trade-offs (CAP theorem)
4. Operational complexity

Berikan assessment dalam format: risk level (high/med/low), 
description, recommendation.

[DESIGN DOC]

Tips: Kombinasikan role dengan constraint yang spesifik. "Anda adalah arsitek software" kurang efektif dibanding "Anda adalah arsitek software di perusahaan fintech yang menjalankan 1000+ microservices dengan SLA 99.99%."

Meta-Prompting

Menggunakan LLM untuk menghasilkan, mengevaluasi, atau mengoptimalkan prompt itu sendiri. Berguna ketika sulit merumuskan prompt manual, atau ketika Anda ingin mengeksplorasi ruang prompt secara sistematis.

Pattern 1: Prompt Generation

Saya butuh prompt untuk tugas: [DESKRIPSI TUGAS]
Target model: GPT-4o
Output yang diinginkan: [DESKRIPSI OUTPUT]
Buatkan prompt yang akan menghasilkan output optimal.
Sertakan: system prompt, instruction, format spec.

Pattern 2: Prompt Critique

Berikut adalah prompt dan output yang dihasilkannya:

PROMPT: [PROMPT]
OUTPUT: [OUTPUT]

Analisis: Apa yang salah dengan prompt ini? 
Bagaimana cara memperbaikinya? Berikan versi revisi.

Pattern 3: Automatic Prompt Engineering (APE)

Generate N variasi prompt, jalankan pada test set, dan pilih prompt dengan performa terbaik. Ini adalah dasar dari tool seperti DSPy yang secara otomatis mengoptimalkan prompt berdasarkan metrik evaluasi.
