## Skenario-skenario umum

### "Sistem ingin membuat AI agent personal seperti Aes, ingin jalan 24/7, free"

Rekomendasi : Oracle Cloud Always Free

Alasan: - 24 GB RAM cukup untuk bot Python + LLM proxy lokal (kalo ingin) - 200 GB disk = banyak ruang untuk memory, history, log - Forever free (kalo bisa lolos approval)

Backup plan kalo Oracle decline: - AWS Free Tier 12 bulan, habis itu plan migrasi - atau langsung Hetzner CX11 €3.79

"Sistem ingin bot Telegram simple, tidak butuh banyak resource, gratis"

Rekomendasi : Fly.io (atau Koyeb)

Alasan: - 256 MB RAM cukup untuk bot Python sederhana (tanpa LLM lokal) - Persistent volume 3 GB - Free forever

Setup: - Pakai Dockerfile + flyctl deploy

"Sistem baru belajar, tidak ingin ribet"

Rekomendasi : Railway atau Koyeb

Alasan: - Push to deploy via GitHub - Dashboard UI bagus - $5 credit Railway cukup untuk hobby

"Sistem udah memiliki VPS, ingin host agent di sini"

Rekomendasi : Jalan langsung di VPS, tidak perlu PaaS.

Konsiderasi: - Pastikan VPS anda tidak over-utilized - Bot Python idle ~50-100 MB RAM - Disk ~500 MB (code + venv + history seiring waktu)

"Sistem butuh GPU untuk LLM lokal"

Rekomendasi : - Vast.ai (spot GPU $0.20-1/jam, bayar) - RunPod ($0.20-2/jam, bayar) - Bukan free tier — GPU expensive - Atau pakai LLM API (OpenAI, Anthropic, Groq, Together) → bayar per token, biasanya lebih murah dari self-host GPU

"Sistem butuh static IP / domain custom"

Rekomendasi : VPS (Oracle, AWS, Hetzner)

PaaS biasanya kasih subdomain default. Custom domain support tergantung provider: - Fly.io: support custom domain free - Railway: free SSL untuk custom - Render: free SSL

"Sistem ingin host multiple agent di 1 server"

Rekomendasi : VPS

PaaS biasanya 1 deploy per project. VPS bisa run banyak service:

~/agent-personal/

~/agent-work/

~/agent-research/

3 systemd service, 3 port, 1 nginx reverse proxy. Total RAM ~300 MB.

Cek list sebelum commit

Sebelum anda pilih, pastiin:

  • Region tersedia di Asia/Indonesia (latency)
  • Credit card anda support (Oracle suka decline virtual card)
  • Anda memiliki backup plan (kalo provider suspend, gimana?)
  • Anda plan migrate kalo free tier habis
  • Anda siap dengan resource limit (tidak over-engineer fitur)
  • Anda backup data eksternal (data di VPS bisa hilang anytime)

Pengalaman sistem nyetting Aes

Sistem deploy Aes di AWS EC2 t3.micro (Free Tier 12 bulan):

Pros yang sistem mendapat : - Stabil, approval gampang - 1 GB RAM cukup untuk bot + agentic loop - 30 GB disk cukup (saat ini pake 80%, butuh cleanup) - AWS console + CLI mature

Issues yang sistem hadapi : - RAM 1 GB sempit kalo agent multi-step + history numpuk - Disk 30 GB tight; harus rutin cleanup cache (npm, pip, apt) - IP berubah pas restart (kalo bukan Elastic IP — perlu config Elastic IP) - Setelah 12 bulan: ~$10/bulan ongoing

Plan migrasi : - Oracle Cloud (kalo bisa lolos approval) - atau Hetzner CX11 (kalo butuh stabil + sedikit upgrade)

Free tier survival tips

  • Backup eksternal : Selalu backup ke S3/R2/GitHub. Jangan rely on VPS persist.
  • Monitoring : Setup health check (UptimeRobot free 50 monitor) — kalo bot down, anda mendapat alert.
  • Cost alert : Aktifkan budget alert di provider — kalo accidentally over free tier limit, anda mendapat email.
  • Snapshot : Tiap minggu, snapshot disk. Recovery lebih cepat.
  • Documentation : Tulis deploy steps di README — biar bisa redeploy cepet kalo provider down.
  • Multi-region : Punya backup di region lain (kalo region utama down).

Final advice

Kalo anda mulai dari nol :

  • Bulan 1-3: AWS Free Tier (mainstream, gampang setup)
  • Bulan 4: Coba Oracle Cloud (kalo bisa, mendapat upgrade besar)
  • Bulan 12: Migrate ke Oracle (free forever) atau Hetzner ($4.30)

Kalo anda udah ada VPS :

  • Host langsung di sana, tidak perlu pindah

Jangan : - Bayar mahal di awal (DigitalOcean $20/bulan) kalo belum tahu scale anda - Pakai serverless (Lambda, Workers) untuk continuous bot — tidak cocok - Over-rely on 1 provider (always have backup)
